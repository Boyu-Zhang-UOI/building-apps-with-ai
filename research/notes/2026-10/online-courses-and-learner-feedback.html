Online, Industry, MOOC, Bootcamp, Cohort and Vendor-Academy Courses on Vibe Coding: What Is New (25 Sept to 21 Oct 2026), Plus Fresh Learner Feedback ​

Research date: 2026-10-21. Baseline: research/notes/online-industry-courses.md (25 Sept 2026, about 40 courses). These notes record only what is new or changed since then, or material the baseline did not capture.

Date conventions:

  • "Page date" is the date shown on the source.
  • "Fetched 21 Oct" means the live page was read today and showed no date.
  • "Search summary" means the fact came from a search engine's summary and not from the page itself. Treat those as lower confidence.

Some catalog pages (Coursera, Class Central, Udemy, WindowsForum) returned 403 errors, as they did in the baseline.

Q1. Which beginner-oriented vibe coding / AI-coding courses launched or were substantially updated between late Sept and late Oct 2026? (module lists, projects, durations, prices, free-tier fit) ​

Takeaway ​

The window is quiet. Only one substantial new free course was found that falls inside it: Microsoft/GitHub's "GitHub Copilot app for Beginners" (28 Sept 2026). It has a setup chapter plus 7 hands-on chapters built around a single sample app, and it is organized around a "trust the evidence" review loop. Copilot Free is not confirmed to work. The other items are small updates, such as a DLAI JetBrains course updated 18 Sept, a Scrimba course re-recorded in Oct, and an OpenAI course localized on 15 Oct, or courses the baseline missed. For most providers (DeepLearning.AI beginner line, Anthropic, OpenAI coding, Google/Kaggle, Coursera, Codecademy, freeCodeCamp, Replit, Lovable, Bolt), no new beginner vibe-coding course was found for 25 Sept to 21 Oct 2026.

Cited Findings ​

Microsoft / GitHub: NEW in window

  • "GitHub Copilot app for Beginners" was announced on 28 Sept 2026 by Dan Wahlin on the Microsoft for Developers blog. It is free and open source. — Microsoft for Developers blog, 28 Sept 2026
    • Structure: "a short setup chapter followed by seven hands-on chapters". — MS Dev blog
      • Ch 00 Setup: install the app, sign in, fork the course repo, and seed practice issues and PRs. About 20 minutes.
      • Ch 1 Tour the App: chats vs project sessions, session modes, model and reasoning settings.
      • Ch 2 Sessions, Worktrees and Context: isolated sessions, git worktrees, and @, # and / context.
      • Ch 3 Development and GitHub Workflows: an inner loop (change, diff, test, preview) and an outer loop (issues, PRs, review comments, failing checks).
      • Ch 4 Skills and Custom Agents: update a review skill, then build a read-only custom agent.
      • Ch 5 MCP Servers and Plugins: the Context7 MCP server and a plugin-supplied skill.
      • Ch 6 Canvases: /create-canvas session board.
      • Ch 7 Automations: turn a manual status report into an on-demand automation, then schedule it and use event triggers.
    • Sample project: samples/book-app-web, a React/Vite/TypeScript book-collection app. It has search, genre and reading-status filters, reading stats, tests and a build step. The project runs through the whole course. — MS Dev blog
    • Each chapter follows the same template: why the topic matters, a real-world analogy, core concepts, hands-on exercises, key takeaways, and an assignment. The course adds a glossary and a companion video series. The analogies are studio-themed: a worktree is a "recording booth", session modes (Interactive / Plan / Autopilot) are a "producer in the control room", a canvas is an arrangement board, and automations are a sequencer. — MS Dev blog
    • The review loop has the learner check the diff in the Changes tab, run tests in the Terminal, and preview in the Browser tab. The post calls this "trust the evidence." — MS Dev blog
    • Prerequisites and cost: the post says learners need a Copilot plan or can sign in with their own model provider. It does not say whether Copilot Free is enough. Some familiarity with GitHub, Git and npm helps; if you can clone a repo and run npm test, the post says you are ready. No AI or agent background is required. There is no stated total duration. — MS Dev blog
    • It is aimed at developers who want to direct agents and review their work, not just chat with them (search summary of WindowsForum coverage dated 28 Sept 2026; the page returned 403). — WindowsForum, 28 Sept 2026
  • The baseline already covered "GitHub Copilot CLI for Beginners" (Mar 2026; 8 chapters; works with Copilot Free). No update to it was found in the window. — MS Dev blog, Mar 2026

Q2. Has Campus × Replit VibeCoding 101 published more detail or outcomes? Any other 6–10 week cohort programs for non-technical learners? ​

Takeaway ​

Yes on detail, no on outcomes. As of 21 Oct 2026 the Campus page carries a week-by-week syllabus that is more fundamentals-heavy than its "vibe coding" branding suggests, covering Python constructs, HTML/CSS/JS, version control, frameworks and APIs. The page also now resolves the earlier credit conflict: the course is offered for college credit. It adds a 200-seat cap, a 101 → 102 certificate path, and about 2 h live plus a couple of hours self-paced each week. The next cohort is TBA, and no completion or outcome data is published. No new 6–10 week non-technical cohort with an Oct or Nov 2026 start was confirmed. The cohorts found for non-coders are mostly 2.5–4 weeks (Maven, Designlab).

Cited Findings ​

Campus × Replit VibeCoding 101 (fetched 21 Oct 2026)

  • Format: 8 weeks, one live online class per week of about 2 hours, plus "a couple of hours" of self-paced work on Replit each week. Capped at 200 students. Live attendance is expected; recordings "may be available". The next cohort and class times are TBA, with a waitlist. — Campus VibeCoding 101
  • Weekly syllabus, as listed:
    1. Fundamentals of programming and AI-assisted development.
    2. Programming languages and their use cases.
    3. Python programs and core programming constructs.
    4. Web apps with HTML, CSS and JavaScript, with AI help.
    5. Industry-standard development tools for code management.
    6. Dynamic web apps using modern frameworks.
    7. Integrating external APIs and AI services.
    8. Deploying and presenting applications to the class.
    • Campus
  • Deliverables: 4 working apps, a personal landing page for the portfolio, and a "flagship milestone project" with clean docs, version history and prompt notes. — Campus
  • Credit and certificate: offered for college credit, and Campus is described as a fully accredited college. There is no audit option. Vibe Coding 101 plus 102 earns a "Certificate in AI Assisted Software Development", and 101 is required before 102. This settles the baseline conflict in favor of the Replit blog's "academic credits" claim. — Campus; Replit blog, 23 Nov 2025
  • Cost: $1,500. A credit card is needed to reserve a seat, and there are no payment plans. 10% of tuition goes to scholarships through The Campus Foundation. Replit access is provided by the program. — Campus
  • Faculty: the six people listed in the baseline, now with fuller bios. They include Vikash Rungta (formerly led Llama Safety and Responsible AI at Meta) and Meredith Syed (formerly led AI developer advocacy at IBM). — Campus
  • Outcomes: none published. There are no completion rates or cohort numbers, and the three testimonials appear only as images. — Campus
  • Caveat: I can't tell whether the syllabus was added after 25 Sept or was missed by the baseline extraction. Treat it as "first captured 21 Oct 2026".

Other cohort programs for non-technical learners (none with confirmed Oct or Nov 2026 starts)

  • Maven "The Marketing Engineer: Vibe Coding for Non-Coders" (Natalie Lambert): a 4-week cohort for marketers and founders using Claude Code or OpenAI Codex, GitHub, Supabase and Vercel. No start date found (search summary). — Maven

Inferences ​

  • Campus, the closest $1,500 analogue to an 8-week course, does not run pure vibe coding. It covers Python constructs in week 3, HTML/CSS/JS in week 4, version control in week 5 and APIs in week 7, and ends with a live presentation. That supports keeping light fundamentals in a free 8-week course and ending with a demo day.
  • "Prompt notes" as a graded part of the flagship deliverable is a cheap idea to copy. It makes the learner's process visible and assessable, which matters when the AI wrote most of the code.
  • The 200-student cap with expected live attendance suggests Campus relies on live teaching, not async video, for support. A free course without live staff needs substitutes such as peer review, office-hour recordings and checklists.
  • Non-technical cohorts on the market cluster at 2.5–4 weeks, often around one paid stack (Supabase, Vercel, Stripe, Claude Code or Codex). An 8-week free-tools course is still unusual.

Gaps ​

  • No Campus outcomes, completion data, cohort dates, 102 syllabus or testimonial text are available.
  • Prices and Oct/Nov 2026 dates for the Maven and Designlab cohorts were not confirmed; the details come from search summaries.
  • Found no other 6–10 week program for non-technical learners with a confirmed autumn 2026 start.

Q3. What do recent learner reviews and discussions praise or criticize in beginner AI-coding courses? ​

Takeaway ​

Very little new learner feedback was dated inside 25 Sept to 21 Oct 2026. The Coursera review pages checked have no reviews from Sept or Oct; the latest are from Aug 2026 (Scrimba) and Apr 2026 (CU). Recent reviews and discussions still sharpen the baseline critiques, though:

  • Tool churn breaks courses. One review notes a course is built on Cursor 1.x and a feature it teaches is deprecated.
  • Setup and free credits. Learners struggle with API keys and burn through free credits.
  • Assessment mismatch. Quizzes don't match the tutorial.
  • Pace. Courses go too fast or skip steps for non-coders, or else are too basic.

An early-Oct 2026 Hacker News thread converges on process discipline for working with agents: small reviewable chunks, specs first, humans own the tests, a second model reviews, and scrutiny scales with the stakes.

Cited Findings ​

Coursera reviews (fetched 21 Oct; none dated Sept or Oct 2026)

  • Scrimba "Vibe Coding Essentials" specialization reviews page: 4.4 average from 49 reviews across 5 courses (68% 5★, 17% 4★, 6% 3★, 4% 2★, 5% 1★). The most recent reviews are 3–4 Aug 2026. — Coursera Scrimba reviews
    • Conflict: the baseline recorded 4.4/5 from 412 reviews on the specialization landing page. The reviews page probably shows a subset; the count is unreconciled.
    • Tool churn: a 4★ review (23 Mar 2026) calls the Cursor course OK as an intro but notes it is based on Cursor 1.x. Reviewers also note deprecated features such as @Web and a changed UI. — Coursera Scrimba reviews
    • Pace: a 2★ review (26 Jan 2026) says the teacher goes too fast and skips essential steps. Another 2★ review (8 Oct 2025) calls it the most basic of introductions. — Coursera Scrimba reviews
    • Setup and credits: learners without GitHub or Cursor experience struggled with steps like API keys, and some burned through free credits. Quizzes did not always match the tutorial. One reviewer advises skipping the course unless you already have Coursera Plus. — Coursera Scrimba reviews
    • Praise: clear, beginner-friendly explanations, hands-on MCP setup examples, and a quick overview of tools. — Coursera Scrimba reviews
  • CU "Vibe Coding Fundamentals": 4.4 from 29 reviews (65.5% 5★, 13.8% 4★, 13.8% 3★, 6.9% 2★). The latest review is 5 Apr 2026. Praise covers beginner suitability, clear instruction and an "AI coach" section that helped learners refine app ideas. Criticism is mainly "Super basic" (3★, 12 Nov 2025). — Coursera CU reviews
    • One review, surfaced in a search summary of a Coursera program-variant page, says a person without programming experience could not learn vibe coding from this course, because terms and tools are explained only briefly. — Coursera CU reviews (program page)

Hacker News (in window)

  • "Ask HN: Is anybody producing good code with coding agents?" (about 3 Oct 2026, i.e. 18 days before 21 Oct; 29 points, 48 comments). Recurring advice:
    • Have the agent do small chunks you can review quickly.
    • Write specs in Markdown and have agents poke holes in them, or let the agent "grill" you with questions before writing the spec.
    • Act as the architect.
    • Keep control of the unit and integration tests.
    • Use multiple models to argue over a change.
    • Treat the agent as a fast typist who needs a full spec and a gate.
    • Vibe-code only low-stakes tools, audit every hunk you care about, and hand-write mission-critical code with an agent as reviewer.
    • Skeptics report "vibing" themselves into a corner.
    • HN item 49934037

Hacker News (just before window, context)

Q5. Concrete, transferable ideas (with evidence) for improving a beginner 8-week course ​

Takeaway ​

The new evidence points to cheap, structural changes rather than new content:

  • A fixed chapter template with analogies, a glossary and an assignment.
  • A visible "trust the evidence" review loop (diff, test, preview).
  • Inner and outer loop framing.
  • Seeded practice issues in a forkable course repo.
  • Prompt notes as a graded deliverable, and a presentation finale.
  • Light fundamentals woven into the weeks (as Campus does).
  • Dated, versioned tool handouts to survive churn.
  • An explicit free-credit budget.
  • Beginner-sized security gates.
  • An optional "rebuild it cheaper or locally" lab.

Cited Findings and design ideas ​

  1. Fixed per-lesson template. Every chapter in the GitHub Copilot app course follows the same sequence: why it matters, a real-world analogy, core concepts, hands-on, takeaways, assignment, plus a course-wide glossary. — MS Dev blog, 28 Sept 2026. This addresses the "terms explained too briefly" critique. — Coursera CU reviews
  2. A named review loop: "trust the evidence". After each agent change, check the diff, run the tests, and preview the app. — MS Dev blog. Practitioners in early Oct 2026 say the same: small chunks you can review, and keep control of the tests. — HN 49934037. Use the 200→500 test-tampering anecdote as the cautionary case. — HN 48662310
  3. Inner and outer loop framing. The inner loop is change → diff → test → preview. The outer loop is issue → PR → review → checks. Teach the inner loop in weeks 2–4 and the outer loop (GitHub issues and PRs) in weeks 5–6. — MS Dev blog
  4. Plan before autopilot. The GitHub course teaches three session modes (Interactive, Plan, Autopilot). — MS Dev blog. HN practitioners advise specs first and letting the agent "grill" you before you write the spec. — HN 49934037
  5. A forkable course repo with seeded practice issues and PRs. The GitHub course's setup chapter has learners fork the repo and seed practice issues and PRs, so the outer loop can be practised on realistic tasks from day one. — MS Dev blog
  6. One running sample app across chapters. Both GitHub beginner courses use one book-collection app throughout. Pair this with the near-universal "second app with the same process" pattern from the baseline. — MS Dev blog; MS Dev blog, CLI course
  7. Prompt notes in the capstone, and a presentation finale. Campus's flagship deliverable requires clean docs, version history and prompt notes, and week 8 is "deploying and presenting applications to the class". — Campus
  8. Weave light fundamentals into the weeks. Campus's 8-week non-technical syllabus includes core Python constructs, HTML/CSS/JS, version-control tools, frameworks and API integration. — Campus. HN discussion stresses that debugging and judgment depend on fundamentals. — HN 48662310
  9. Version-stamp tool instructions and refresh them each term. Reviews criticize a course built on Cursor 1.x with deprecated features. — Coursera Scrimba reviews. Independent reviewers flag courses recorded before protocol changes (MCP). — scrimbaguide.tech. Providers re-record (Scrimba Learn AI Agents, Oct 2026) and update quietly (DLAI updates in Jul–Sept 2026). Keep click-paths in dated Markdown handouts and give each lab a "tested on <date>, tool version" line. — scrimbaguide.tech; DLAI Cloud to Local
  10. Quizzes generated from the current lab. Learners complain that quizzes don't match the tutorial. — Coursera Scrimba reviews
  11. Teach a free-credit budget explicitly. Learners burned through free credits during setup. — Coursera Scrimba reviews. Third-party courses now sell credit saving. — FindSkill. Practical moves: plan in a free chatbot first, batch requests, and switch tools when a quota runs out.
  12. Account-setup week (Week 0). Kaggle and AI Studio sign-up needs a phone number, and some deploy steps need billing. — i-programmer. API-key setup tripped Coursera learners. — Coursera Scrimba reviews. Front-load and test every account before Week 1, and offer a no-phone fallback tool.
  13. Beginner-sized security gates, simplified from Google's secure agentic coding codelab. — Google Codelabs
    • A plain-English security-rules section in the project's context file (CLAUDE.md, AGENTS.md or copilot-instructions).
    • A "Security boundaries" heading required in every plan.
    • A secrets check before every commit, plus GitHub's built-in secret scanning.
    • A simple lesson on why local checks can be bypassed (--no-verify).
  14. Optional "rebuild it cheaper or locally" stretch lab. The DLAI and JetBrains course rebuilds one app with cheaper subagents, then OpenRouter, then a fully local LM Studio model. Present it as a hedge against free-tier limits, optional because it needs capable hardware. — DLAI Cloud to Local
  15. Second-model review. HN practitioners report that having a different model review a change catches more than a single reviewer does. For free-tier learners: paste the diff into a second free chatbot and ask what could break. — HN 49934037
  16. Scrutiny proportional to stakes. Vibe-code throwaway tools and audit what matters. Make this explicit as a rubric dimension: the learner states the stakes for each project and the matching review level. — HN 49934037
  17. In-tool lessons as a delivery format. CC for Everyone runs each lesson as a slash command inside the coding tool. A free-tools course could ship lesson prompts or "skills" files in the starter repo that the learner runs inside Copilot or Gemini CLI. — ccforeveryone.com
  18. Tool-agnostic pre-work on judgment. Assign Anthropic's AI Fluency (the 4D framework, including "Discernment") and Capabilities and Limitations as Week 0 reading, so learners arrive with a verification mindset. — academy.claude.com. This directly targets the novice pattern of more prompting and less reviewing. — arXiv 2512.02750

Inferences ​

  • The most valuable change for an existing course is probably to make verification visible and graded: the diff, test and preview loop; prompt notes; a stakes statement; a second-model review. Review and verification are what novices skip (research), what practitioners stress (HN), and what new vendor curricula are built around (GitHub's "trust the evidence").
  • Tool churn is the most cited fixable complaint. A repo-based, date-stamped handout system plus a per-term refresh pass is low cost and answers it directly.
  • The market still has almost no free, 8-week, multi-tool beginner course. Campus charges $1,500, and the Maven and Designlab programs run 2.5–4 weeks on paid stacks. The existing course's niche is intact as of 21 Oct 2026.

Gaps ​

  • None of these ideas has outcome data (completion, learning gains) from the providers. Evidence is design precedent, reviews and practitioner opinion, not controlled studies.
  • It is unverified whether GitHub's "trust the evidence" loop works for learners without Git or npm experience.
