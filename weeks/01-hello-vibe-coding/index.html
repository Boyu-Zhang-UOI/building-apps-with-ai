Week 1 — Hello, Vibe Coding ​

You can build a working web page just by describing it to an AI, but you only own it once you can explain what is inside and change it yourself.

Learning objectives ​

By the end of this week you can:

  1. Explain what "vibe coding" originally meant, and how it differs from agentic engineering.
  2. Describe how a large language model (LLM) produces code, and why that means you must check it.
  3. Name the three languages of a web page (HTML, CSS, JavaScript), say what each does, and find each in a one-file page.
  4. Build a one-file page with the loop describe → generate → run → customize, writing prompts in four parts: Goal · Context · Constraints · Done when.
  5. Ask an AI to explain code, and check the explanation against the code and the page.
  6. Change a page's HTML, CSS and JavaScript by hand, with no AI, predicting the result first.
  7. Set your AI tools' privacy settings and say what you must never paste into one.

Before class ​

  • ☐ Finish the part of the week 0 pre-work that comes before the first class: a GitHub account, a personal Google account (school or work accounts often block Gemini), and the privacy settings on every AI tool you plan to use.
  • ☐ Skim From Python to JavaScript (about 15 minutes). Your page's behavior is written in JavaScript; this page maps it onto the Python you know. You'll have it open in Studio B.
  • ☐ Bring a laptop and charger, and check you can sign in to Google and GitHub on it.
  • ☐ Think of three things about yourself you're happy to make public: a first name or nickname, some interests, something you're learning.

The rest of week 0 (signing the safety contract, the self-assessment, GitHub Education) is part of this week's homework.

Key ideas ​

If you are working through this week on your own, read this section, then do the lab. The self-paced path says what to do instead of the pair and class activities.

Vibe coding, then and now ​

In February 2025 Andrej Karpathy described vibe coding: accept everything the AI writes without reading it, and paste any error back in. Fine, he said, for throwaway projects (his post, reproduced in Geng et al.). Simon Willison's golden rule drew the line: never commit code you couldn't explain to someone else (Willison, 2025). By 2026 Karpathy contrasted it with agentic engineering: building serious software with AI agents while staying responsible for understanding and securing it (Karpathy, 2026). This course starts at the vibe-coding end and adds one engineering habit a week.

How an LLM writes code ​

A large language model predicts what text comes next, one token (a word or piece of a word) at a time. Code is text, so it predicts code the same way. Four consequences matter every day:

  • It only sees its context window: this chat and anything you paste in. Not your screen, not your files.
  • The same prompt can give different answers.
  • It can be confidently wrong. It produces plausible text, not checked facts (hallucination).
  • It has a knowledge cutoff, so it may not know recent tools or changes.

So you check its work by running it and reading it. Being able to program doesn't make checking optional: in a 2025 trial, experienced developers using AI were 19% slower while believing they were faster (METR, 2025).

What a web page is ​

A web page is a text file your browser reads and runs:

LanguageJobExample
HTMLStructure: what is on the page<h1>Hi, I'm Sam</h1>
CSSStyle: how it looksh1 { color: teal; }
JavaScriptBehavior: what happens when you click or typebutton.addEventListener("click", wave);

Where a Python script runs top to bottom and ends, a page's JavaScript mostly waits for events (a click, a key press) and runs a function when one happens, changing the page through the DOM, the browser's live model of the HTML. This week all three live in one file, index.html.

The loop, then the hand changes ​

Describe → generate → run → customize: describe what you want in four parts, let the AI generate it, run it in the live preview, then ask for one change at a time. From week 3 this grows into the full Safe Loop.

An AI can write the page, but it can't understand it for you. So in Studio B you ask it to explain each part, check the explanation, and change the code yourself with the AI off: your first practice of the six skills you must show without AI.

AI on, AI limited, AI off ​

Every task carries a label. 🟢 AI on: use AI freely. 🟡 AI limited: the AI may comment or hint, but the work is yours. 🔴 AI off: close the AI tabs and work alone. Full policy: assessment guide.

Privacy and the safety contract ​

Free AI tools may store your chats, train on them and let people review them. Turn training off where you can, and never paste passwords, keys or other people's personal information: the first two rules of the safety contract, which you sign on Canvas this week. Your page will be public, so treat everything in it as public. Personal writing goes on Canvas, never in a repository (Privacy of your work).

Understanding check ​

At the end of Studio B you complete the Week 1 exit ticket with 🔴 AI off: explain parts of your own page in plain English, and why an AI can give two different answers to the same question. It's scored for completion, not correctness.

Homework ​

About 5 hours, including project time; details on the homework page. Finish your page and add one small feature written entirely by hand (🔴 AI off), then upload it to Canvas · the first half of the AI Fluency course · the week 0 tasks (safety contract, self-assessment, GitHub Education) · a reflection on Canvas (🔴 AI off). Graded on effort and completion of the core tier (rubric).
