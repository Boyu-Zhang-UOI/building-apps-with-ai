Week 1 Lab — Hello, Web ​

Goal: in Studio A, build a one-file personal home page with an AI and save it. In Studio B, have the AI explain it section by section, then change its HTML, CSS and JavaScript by hand. Time: two 75-minute studios, with about 40 minutes of lab in each. You need: a laptop, your personal Google account, and the privacy settings from week 0. Next week you publish the page on GitHub.

AI-use key: 🟢 AI on: use AI freely · 🟡 AI limited: the AI may comment or hint, but the work is yours · 🔴 AI off: close the AI tabs and work alone.

Studios are graded on effort, not polish (rubric): a part that didn't work, with the exact error and what you tried, still counts.

You use the simplest version of the course workflow: describe → generate → run → customize. You describe the page, the AI generates the code, you run it in the live preview, and then you customize it one change at a time.

Stuck for more than 5 minutes? Check Troubleshooting, ask a neighbor, then raise your hand. Using a screen reader or only a keyboard? See the Screen reader and keyboard guide; if a chat tool's code view is hard to use, the local-file route in No preview? Run it yourself lets you work in your own editor.

Before the lab: a welcome, the concept talk and a live demo (30 minutes). The studio ends with a checkpoint share: show a neighbor your page and the prompt that changed it most.

Part A1 — Privacy check (5 min) ​

Why: free AI tools may store your chats, train on them and let human reviewers read samples. You set the privacy settings in week 0; now check they stuck.

  1. In one browser tab, open the Privacy settings page.
  2. In another tab, sign in to Gemini at gemini.google.com with your personal Google account. A school or work account may block Gemini or hide its Canvas tool.
  3. Check that Gemini's Keep Activity is off, as described in the Gemini section. If you plan to use a fallback (ChatGPT or Claude), check its setting too.

NOTE

With Keep Activity off, Gemini doesn't keep your chats: when you close the tab, the chat is gone, and you can't reopen it or share a link to it later. That's fine. In Part A3 you save your code and prompts yourself.

WARNING

Your page will be public from next week. Use your first name or a nickname. Do not put your surname, email, phone number, address, student ID or anything about other people into the page, and do not paste any of it into the AI.

✅ Checkpoint: you are signed in to Gemini with a personal account, and Keep Activity is off.

Part A2 — Build "Hello, Web" (25 min) ​

🟢 AI on.

Open the live preview ​

  1. In Gemini, start a new chat.
  2. Turn on Canvas: look for it under Tools (or a + menu) in the prompt box. A live preview shows the page running next to the chat.

NOTE

Menus move. If you can't find Canvas, start your prompt with "Use Canvas to…", or ask Gemini where Canvas is. Using a fallback? Claude shows a live preview called an Artifact (18+ only); with ChatGPT, see No preview? Run it yourself. Your instructor tells you which tool leads this week.

Your first prompt ​

A good prompt has four parts: Goal · Context · Constraints · Done when. You'll study them properly in week 3; for now, fill in the blanks. Replace everything in [square brackets]. More starters: Prompt starters.

text
Goal: Make a one-page personal home page about me that I will publish on the web.
Context: I'm in a course called Building Apps with AI. I know some Python, but I'm new to HTML, CSS and JavaScript. The page is for classmates and friends. About me: my name is [first name or nickname]. I'm interested in [interest 1], [interest 2] and [interest 3]. Right now I'm learning [something]. I like the colors [color 1] and [color 2].
Constraints: One single HTML file with the CSS and JavaScript inside it. No frameworks, no libraries, no external images or fonts. It must look good on a phone and on a laptop. Keep the code readable, with a short comment at the start of each section. Do not add an email address, phone number, surname or social-media links.
Done when: The preview shows my name as a big heading, a short "About me" paragraph, a list of my interests, and one button that shows a random fun fact about me, picked from a list of five, each time I click it.

Send it. Gemini writes the code and shows it in the Canvas panel. Look for a Preview view (the page) and a Code view (the text that makes it). Copy the prompt into a scratch note (paper or a notes app); next week it becomes your first entry in PROMPTS.md.

✅ Checkpoint: the preview shows a page with your name as a heading, an "About me" section, your interests and a button. Click it a few times. A fact appears, and it changes.

TIP

Your page looks different from your neighbor's even with the same prompt. That's normal: the model picks among likely answers, so each run differs.

Customize: at least 3 iterations ​

Now improve the page one change per prompt. Small, specific requests beat "make it better", and when something breaks you know which change did it. In your scratch note, write down each prompt and what happened.

Use these, the customization prompts (phone layout, footer, fonts, animation), or your own:

text
Goal: Change the color scheme.
Context: The page you just made.
Constraints: Keep everything else the same. Make sure text is easy to read against the background.
Done when: The background and headings use [color] and [color], and all text is still readable.
text
Goal: Add a "Things I'm learning" section with three short items.
Context: The page you just made. The items are: [item], [item], [item].
Constraints: Match the style of the existing sections. Don't change other sections.
Done when: The new section appears below "About me" and looks like it belongs.
text
Goal: Make the fun-fact button more fun.
Context: Right now the button shows a random fact from a list.
Constraints: Plain JavaScript only, no libraries. Keep the list of facts where it is.
Done when: Clicking the button [describe what you want: e.g. makes the fact fade in, or changes the button's label to "Another one!"], every time it's clicked.

Before each prompt, predict what will change; afterwards, check the preview against your "Done when". If a change makes things worse, say so: "That broke the layout on narrow screens. Undo that change."

TIP

If the AI keeps failing at the same thing after two attempts, stop. Start a fresh chat, paste your current code, and describe the problem more precisely. That's the two-strikes rule, and you'll use it all course.

Don't close the chat tab until Part A3 is done: with Keep Activity off, a closed tab is a lost chat. (Lost it anyway? Start a fresh chat with the same first prompt. The second build goes faster.)

✅ Checkpoint: you have sent at least 3 customization prompts, the preview shows your improved page, and your scratch note lists what each prompt did.

No preview? Run it yourself ​

If your assistant shows code but no live preview (see the Tool Handout), run the code yourself. You'll use the same steps in Studio B. Use the copy button on the code block so you get exactly the code, without extra lines such as ```html.

  1. Open a plain-text editor: Notepad on Windows, TextEdit on a Mac (then choose Format → Make Plain Text), the Text app on a Chromebook, or a code editor you already use, such as VS Code. Not Word or Google Docs: they add formatting the browser can't read.
  2. Paste the code and save it as index.html (on Windows, set "Save as type" to All files).
  3. Double-click the file to open it in your browser.
  4. After each change, paste the new code (or type your edit), save, and refresh the browser.

Want your page online straight away? The publishing steps are in week 2's lab, and they work any time.

Part A3 — Save your work (10 min) ​

Why: Studio B starts from your file, and the chat won't be there any more. Your code and your notes must be.

  1. Get the file.
    • If your tool has a Download button, download the file. Check its name: it must be exactly index.html (all lowercase). Rename it if it's index (1).html, Untitled.html or index.html.txt.
    • If there's no download, open the Code view, use its copy button (or click in the code, then Ctrl+A / Cmd+A and copy), and save the code as index.html with the steps in No preview? Run it yourself.
  2. Check it. Double-click index.html. Your page opens in the browser, and the button works.
  3. Keep it where you'll find it: the Desktop or Documents folder (on a Chromebook, My files). Can't save files on this computer? Paste the code into a private document you can open in Studio B.
  4. Keep your scratch note: your first prompt, and the customization prompt that worked best (or went most wrong).

✅ Checkpoint: index.html opens in your browser from your computer, and your scratch note is safe.

Part A4 — Keep customizing, or try a second assistant (if time) ​

🟢 AI on. Pick one:

  • More iterations. Add a footer, a phone layout or an animation from the customization prompts. Save index.html again afterwards (Part A3).
  • Same prompt, second assistant. Send your first prompt, unchanged, to a second assistant from the Tool Handout. How different is the result? How many lines is each?

Checkpoint share (end of Studio A) ​

Show a neighbor your page and read them the prompt that changed it most. If your instructor asks, post a screenshot of your page where they say (crop out other tabs and anything personal). Stuck? Share the exact blocker instead: that counts too.

Working alone? Write one sentence in your scratch note: which prompt changed your page most, and how.

Mini-lesson — Reading a page as a programmer (5 min) ​

You already know what a variable, a list and a function are. What's new is where they live:

  • HTML is made of elements: an opening tag, content, a closing tag, as in <li>Hiking</li>. Extra settings inside the opening tag are attributes: <button id="fact-button">.
  • CSS is a list of rules: a selector saying what to style, then declarations in braces. button { background: teal; } styles every button.
  • JavaScript finds an element (document.getElementById("fact-button")) and attaches an event listener: a function the browser calls when something happens, such as a click.

Where JavaScript trips up Python programmers in a page like yours:

In your page's JavaScriptThe Python you know
const facts = ["…", "…"]; (let if you'll reassign it)facts = ["…", "…"]
facts.lengthlen(facts)
facts.push("…")facts.append("…")
Blocks use { }; indentation is only for peopleIndentation is the block
=== to compare (JavaScript's == converts types first; avoid it)==

The full comparison is in From Python to JavaScript.

Part B1 — Take a guided tour of your code (15 min) ​

🟢 AI on.

Why: right now the page works and you don't know why. "If you can't explain it, you didn't build it." This part is where you start to own it.

Start a new chat and paste your whole file: the AI doesn't remember Studio A.

text
Goal: Help me understand the page in the code below.
Context: I know some Python, but I'm new to HTML, CSS and JavaScript. Here is my page: [paste the complete index.html]
Constraints: Don't change the code. Go through it section by section, from top to bottom. For each section, quote its first line, label it HTML (structure), CSS (style) or JavaScript (behavior), and explain in one or two plain-English sentences what it does. Where the JavaScript works differently from Python, say how in one line.
Done when: I could point at any part of the page in the browser and find the code that makes it.

Read the answer with your editor open next to it. For each section, find it in the code and on the page.

Then ask at least one follow-up about something you don't understand, for example:

text
What does the line starting with "[paste the line]" do? What would happen if I changed it to [this]? Predict it, then tell me how I can check.

Check the tour. Explanations can be wrong too. Pick one claim the AI made ("this rule sets the heading color") and test it in Part B2.

✅ Checkpoint: you can point to (1) the HTML for your heading, (2) the CSS rule that sets the background color, (3) the list of facts in the JavaScript, and (4) the function that runs when the button is clicked.

Part B2 — Change it by hand (20 min) ​

🔴 AI off. Close the AI tabs. You may use your file, the browser, the bridge page and MDN, the standard web reference. Skip the AI summaries search engines put above their results: they count as AI.

Make these four changes, one at a time. Predict what you'll see before you refresh.

#LanguageChangeExample
1HTMLAdd one element: another item in a list, or a new paragraph in a section<li>Rock climbing</li>
2CSSChange a color or a size in an existing rulebackground: #f5f5f5; → background: lavender;
3CSSAdd a new rule: a hover style for your buttonbutton:hover { background: navy; }
4JavaScriptAdd a sixth fact to the button's list (an array: JavaScript's list), then click until it appears"I've hiked in three countries.",

Colors to try: tomato, gold, seagreen, rebeccapurple, lavender, navy.

Done early? Make the button count: show "Fact 4 of your visit" (or similar) above the fact. You'll need a counter declared with let outside the click function, a += 1 inside it, and textContent to show it.

NOTE

If something breaks, undo with Ctrl+Z (Windows, ChromeOS) or Cmd+Z (Mac). A missing ;, }, >, comma or quote mark is the usual cause. Broken HTML or CSS usually still shows something; one typo in the JavaScript stops the whole script, so the button goes dead. (The browser's Console shows the error message. You'll learn to read it in week 7.)

In your scratch note, write down each change: what you changed, from what to what, and what happened. Next week they go into the Ownership statement of your PROMPTS.md (what you wrote or decided yourself).

IMPORTANT

The AI can't see edits you make outside its chat. If you edit the file and then want the AI to make another change, paste your current code into the chat first. That's the context window from the concept talk. (Edits typed into Gemini's Canvas are usually visible to Gemini; if it seems to ignore them, paste the code back in.)

✅ Checkpoint: the browser shows all four changes, the button still works (with your new fact in its list), and you can say which line you changed for each.

Part B3 — Save and log (5 min) ​

  1. Save index.html, close it, and double-click it once more to check it opens with all your changes.
  2. Upload it to Canvas, the course's learning management system (not Gemini's Canvas tool), as the assignment "Week 1 page". Until your page is on GitHub next week, that copy is your backup. You can upload again later in the week.
  3. Check your scratch note has your prompts and all four hand changes.

✅ Checkpoint: your latest index.html is on Canvas, and your scratch note lists every change you made by hand.

Part B4 — Break it on purpose, or start the homework (15 min, if time) ​

🔴 AI off for the breaks. Pick one:

  • Break it on purpose. One at a time, and undo each before the next: delete one } in the <style> section; delete one > from an HTML tag; delete one ) in the <script> section. Refresh after each and note what happens. Browsers try hard to show something for broken HTML and CSS, which is why broken code can look almost right; broken JavaScript simply stops.
  • Start homework task 2: a small feature written entirely by hand (homework).

Before you leave Studio B ​

  • ☐ index.html with your hand changes is saved on your computer and uploaded to Canvas.
  • ☐ Your scratch note has your prompts and your hand changes.
  • ☐ You did the Week 1 exit ticket (🔴 AI off). It's scored for completion, not correctness.
  • ☐ You know what's in the homework, including the first half of the AI Fluency course.

If your tool is down ​

Switch to a fallback for the chat-assistant layer in the Tool Handout: Claude (Artifacts) has a live preview (18+ only); ChatGPT gives code you run yourself (No preview? Run it yourself). The prompts in this lab work unchanged. If you switch partway, paste your current code into the new chat first: the new tool starts with an empty context window.
