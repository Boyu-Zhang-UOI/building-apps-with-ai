Week 8 Homework — Project 1 final ​

Due before next week's Studio A (week 9; default 11:59 pm the night before) · Core: about 5½ hours, including project time, required · Stretch: optional

Deliverables checklist ​

In your public Project 1 repository:

  • ☐ Every MUST criterion passes on your GitHub Pages site (or was moved to SHOULD, with the reason in your README's "Known issues")
  • ☐ Plain index.html, style.css, app.js and lib/ modules: no frameworks, no build step, no npm packages
  • ☐ At least three automated tests of your pure logic passing with npm test, each seen failing once, output in TESTS.md
  • ☐ TESTS.md: a manual test for every criterion, at least 3 edge-case tests, results dated, "Bugs found by testing" with commits
  • ☐ SPEC.md up to date, including the criterion for the function you wrote by hand
  • ☐ README.md: live link, "How it works", acceptance table, known issues, credits
  • ☐ PROMPTS.md covering weeks 5–8 (details in task 6)
  • ☐ At least 6 small commits with clear messages, including at least one git revert
  • ☐ No real personal data about other people, and no classmates' names, anywhere in the repository

On Canvas (private: never in your repository):

  • ☐ Your week 8 reflection, written without AI, and the anonymous mid-course survey
  • ☐ Your repository link and your GitHub Pages link

Also: oral walkthrough 1 done, in a studio or office hours (you can retake it once within 7 days), and codespaces stopped.

This is the finish line for Project 1 (brief, rubric). 🟢 AI on for fixing: Copilot's Ask mode or your chat assistant, no agent mode yet (week 11). Use the Safe Loop for every change: check first, one step, test, read the diff, teach back, commit.

Core ​

1. Make every MUST criterion pass (about 2 hours) ​

Carry on from last week's list, the same way: check first, fix, test, read the diff, teach back, commit. If you change a criterion instead of the code, change SPEC.md and say why in the commit message.

✅ Checkpoint: every MUST criterion passes on your GitHub Pages site, not only in the Codespace preview. Test it on your phone too.

2. Finish your automated tests (1 hour) ​

  1. Finish lab Part A2 if needed: at least three tests (normal, boundary, empty), each seen failing once.
  2. Write one more test first, for an input your app should handle, before you look at whether the function handles it: accents or emoji ("Café ☕"), a number typed as text ("42"), a tab on its own ("\t"). Predict the result, run npm test, and write in PROMPTS.md whether you were right. If it fails, decide yourself whether the function or the test is wrong, and say why.
  3. Paste the summary lines of npm test (the pass and fail counts) into TESTS.md, and commit.

Never change a test just to make it pass.

3. Finish TESTS.md (45 min) ​

Complete last week's TESTS.md: a manual test for every criterion (including your hand-written function's), at least three edge cases marked "(edge case)", the Automated tests table, and every test run on your live site with the date. Fill in Bugs found by testing with the commit that fixed each one. Anything you can't fix goes into "Known issues": an honest known issue never costs points.

4. Finish your README (30 min) ​

Your README (from the Project README template) needs:

  • The live link and, if you like, a screenshot.
  • How it works: the 3–6 sentences you drafted last week, in your own words (you'll explain them out loud), plus the table: which file does what (including lib/ and tests/), what is saved in localStorage and in what format (for example, "a JSON array of plants under the key plants"), and "Authorization: n/a, single-user app; data stays in your browser".
  • Run it yourself: "Open the live site. To run it in a Codespace: python3 -m http.server 8000 and open the forwarded port. To run the tests: npm test."
  • Status against the spec: every criterion, marked ✅ passes or ⚠️ partly, with a note for anything that doesn't fully pass.
  • Known issues and next steps, and Credits for anything you used from other people.

5. Walkthrough 1 (15 min, if not done in a studio) ​

Book an office-hours slot this week. Before you go, read What to expect, commit everything, and practice explaining your save and load lines and your hand-written function.

6. Update SPEC.md and PROMPTS.md (30 min) ​

  • SPEC.md: the criterion for your hand-written function is there, every criterion matches the finished tool, and "Last updated" has today's date.
  • PROMPTS.md covers weeks 5–8: your Goldfish test, key prompts, what the AI got wrong and how you noticed, checks written first, teach-backs, the function you wrote by hand (its check, the review, what you accepted), and What I wrote or decided myself.

7. Reflection on Canvas (30 min) ​

Use the four headings of the reflection template, on Canvas. Anchor it in a concrete moment: a line you wrote by hand, the moment a test turned red when you broke the code, a question in your walkthrough. Then answer in two or three sentences: which part of your Project 1 could you explain least well this week, and what will you do about it?

🔴 AI off. 150–300 words, graded on specifics, not polish (reflection rubric). It goes on Canvas, not in your repository.

8. Mid-course survey (10 min) ​

🔴 AI off. Fill in the anonymous mid-course survey your instructor shares on Canvas. It asks what's working, what isn't, and how confident you feel explaining your own code. You're halfway through the course: honest answers change the second half. Self-paced learners: answer the same three questions at the end of your reflection.

IMPORTANT

Minimum to keep up: Project 1 is live, and npm test runs at least three passing tests of your own logic. Week 9 starts from a Node project with tests.

Fallen behind? Tell your instructor early. A grace token can buy you time on Project 1, and you can practice the testing steps on the rescue starter before week 9.

Stretch (optional) ​

A. Test a second module ​

Move another calculation (a total, a streak, a sort) into its own file in lib/, with at least two tests written first, one of them an edge case.

B. Catch the clinic's bug 3 with a test ​

In the clinic, 40 + "5" became "405". Write a test for a pure addPages(pagesRead, typed) that fails if the typed text isn't converted, then make it pass. What should it do with "abc" or "-5"? Test those too.

C. Get ahead on week 9 ​

Skim the How the Web Works sections on requests, APIs and the trust boundary.
