Week 8 Lab — Own It ​

AI-use key: 🟢 AI on: use AI freely · 🟡 AI limited: the AI may comment or hint, but the work is yours · 🔴 AI off: close the AI tabs and work alone.

In Studio A you practice the git commands that show and undo your changes, with the AI off, then write automated tests for your Project 1's logic. In Studio B you write a function yourself from a short spec, and finish Project 1 in project time.

You need: your Project 1 repository and Codespace, and a GitHub account with Copilot switched on (accounts).

Using a screen reader or only a keyboard? See the screen reader and keyboard guide.

Part A1 — Git log, diff and revert (20 min) ​

🔴 AI off. Reverting a bad commit is one of the six skills you must show without AI.

Why: your history is a debugging tool. It tells you what changed, when and why, and it lets you undo a change without losing anything. More: Git Cheat Sheet.

Commit anything you want to keep first, so the practice starts clean. Keep the web server running: click the + icon in the terminal panel to open a second terminal, and type these there.

  1. See your history, newest first. Each line starts with a short commit id:

    bash
    git log --oneline

    If the list fills the screen and won't go away, press q.

  2. See what your latest commit changed (red lines removed, green lines added; q to get back):

    bash
    git show HEAD

  3. See what you've changed but not committed. In index.html, change the text inside <title>…</title> and save. Then:

    bash
    git diff

    That's your change, before any commit. When something breaks and you don't know why, git diff is a second way to find the line that changed. Now throw the change away:

    bash
    git restore index.html

    git restore discards uncommitted changes to a file git already tracks. There's no undo, so use it only on changes you don't want. Run git diff again: nothing.

  4. Make a bad commit on purpose. Add this line at the very end of style.css and save:

    css
    body { display: none; }

    Then commit it:

    bash
    git add style.css
git commit -m "Hide everything (bad commit on purpose)"

    Reload the preview: the page is blank, and the Console has no error. (Blank page, clean Console? Suspect CSS.)

  5. Undo it with a revert. A revert makes a new commit that undoes an old one, so your history stays honest:

    bash
    git revert HEAD --no-edit

    (--no-edit accepts git's ready-made message, "Revert …". Without it, git opens an editor for the message.)

  6. Check and push. Reload the preview: the page is back. Then:

    bash
    git log --oneline
git push

WARNING

In this course, never use git reset --hard or git push --force to undo work. They delete history, and they're the commands agents have used to destroy work. git revert is always safe.

Think about it: to undo a commit further down the list, you'd use git revert [its commit id]. That's the answer to "a change two commits ago broke everything".

✅ Checkpoint: git log --oneline shows your bad commit followed by a "Revert …" commit, your app looks normal, and git push has finished.

Part A2 — Test your Project 1 logic (25 min) ​

🟡 AI limited. You write the tests. Copilot's Ask mode may explain test output, or suggest edge cases you missed. If you ask it for test ideas, ask in a prompt that doesn't include your function's code, so the ideas aren't bent to fit it.

Why: Project 1 needs at least three automated tests of its pure logic. Week 4 showed you the pattern and week 6 used it to check first. Now you test the calculations and checks your spec depends on, including the edges you found last week. Finish here, in Part B2, or in homework.

1. Check your set-up. In your second terminal, run npm test. If it runs your week 6 test, go to step 2. If it says there's no package.json, create one in the top folder of your repository, with your repository's name:

json
{
  "name": "plant-tracker",
  "private": true,
  "type": "module",
  "scripts": {
    "test": "node --test"
  }
}

node --test finds every file whose name ends in .test.js (for example in a tests/ folder) and runs it. Your tests import from a module: a file that exports functions, like a Python module you import from.

2. Find your untested logic (5 min). Since week 6, your rules live in lib/. List the ones without a test yet, and look in app.js for any check or calculation the AI left there: checking input, counting, totals, sorting or filtering, dates, streaks, scores. A function is easy to test when the same inputs always give the same output: no document, no localStorage, and no clock. If it needs today's date, pass the date in as an argument, as the rescue starter does in lib/sessions.js.

If a calculation is tangled up with the page, pull it out. For example, a draw function that adds up minutes as it builds the list becomes:

js
// lib/stats.js
export function totalMinutes(sessions) {
  return sessions.reduce((sum, session) => sum + session.minutes, 0);
}

3. Move it into lib/, if it isn't there yet. Put the function in lib/[name].js with export in front, and import it at the top of app.js. The path needs ./ and the .js ending, unlike a Python import:

js
import { totalMinutes } from "./lib/stats.js";

Your index.html should already load app.js as a module (week 6). If it doesn't, change its script tag:

html
<script type="module" src="app.js"></script>

WARNING

Three things change when app.js becomes a module. (1) onclick="someFunction()" in your HTML stops working, because module functions aren't global: switch to addEventListener, or ask Copilot (Ask mode) to explain how. (2) You can't type your variable names into the Console any more; use console.log instead. (3) Modules only work through a web server (your preview or GitHub Pages), not by opening index.html from your computer's files.

4. Write the tests. Aim for three behaviors, each with a name that says what should be true: the normal case (an example from your spec), a boundary (exactly the limit, one over), and the empty case (an empty list, an empty string, 0). For example, tests/stats.test.js:

js
import { test } from "node:test";
import assert from "node:assert/strict";
import { totalMinutes } from "../lib/stats.js";

test("adds up the minutes of every session", () => {
  assert.equal(totalMinutes([{ minutes: 25 }, { minutes: 50 }]), 75);
});

test("an empty log adds up to 0", () => {
  assert.equal(totalMinutes([]), 0);
});

assert.equal(actual, expected) checks a single value. For arrays and objects, use assert.deepEqual, which compares contents: in JavaScript [1, 2] === [1, 2] is false, unlike Python's ==.

Check first for anything the function doesn't do yet: if your spec names a limit your code ignores, write that test before you change the function, and watch it fail.

5. Run them, commit, and see each one fail once. Run npm test: you should see a ✔ for each test, and fail 0. Commit (Add tests for totalMinutes (AC5)). Now break the function on purpose (flip a comparison, change a limit, return early), run npm test again, and read the output: which test failed, what it expected, and what came back. Then undo the break with the command from Part A1, using your own file name:

bash
git restore lib/stats.js

Repeat with a different break until every test has gone red once. A test you've never seen fail may not be checking anything.

6. Record it. Add each test file to the Automated tests table in TESTS.md (from the TESTS template), paste the last lines of the npm test output under it, and commit.

Never change a test just to make it pass. If a test seems wrong, decide yourself whether the test or the function is wrong, and write down why.

✅ Checkpoint: npm test passes at least three tests of your own logic (counting your week 6 test), and you've watched each one fail once on purpose.

Part B1 — You write it (30 min) ​

🟡 AI limited. You write every line. Copilot's Ask mode may review your change and answer questions; it doesn't write code, and inline suggestions stay off.

Why: in CMU's AI coding course, understanding peaked on the assignment where students partly wrote the code themselves (CMU 15-113). Each card below is a short spec: a criterion, the function's inputs and output, and examples. You write the function. A skeleton with blanks is under Hint, if you're stuck. This is the "function you wrote yourself" that the Project 1 brief asks for.

  1. Switch inline suggestions off in this workspace (chat stays on): Command Palette (Ctrl+Shift+P, or Cmd+Shift+P) → Preferences: Open Workspace Settings → search inline suggest → untick Editor › Inline Suggest: Enabled. Menus move: if this doesn't match, ask your instructor.

  2. Pick one card (below). Add its criterion to your SPEC.md as your next AC number.

  3. Check first. For card A or B, create its test file (tests/count.test.js or tests/duplicates.test.js) with one test per row of the card's table, and run npm test: red, because the function doesn't exist yet. For card C, write its manual test in TESTS.md. In PROMPTS.md, start an entry, "Function I wrote by hand: [card]", and say what your check is.

  4. Find your three names in app.js, and write them down:

    • your list variable: the array your items are kept in (it's what goes inside JSON.stringify(...));
    • your draw function: the function that empties the list on the page and adds every item again;
    • your storage key: the first text inside localStorage.setItem("…", …).

  5. Write the function (about 12 minutes). Type it yourself, don't paste. Stuck for 5 minutes? Open the card's hint. Run npm test until it's green, then connect the function to your app, reload the preview and run the card's manual check. If something breaks, read the Console first.

  6. Ask for a review. In Source Control, click your changed file to see the diff. Open Copilot Chat, choose Ask in the mode picker at the bottom of the chat box, and send:

    text
    Goal: Review the function I just wrote by hand, before I commit it.
Context: #changes. I added [the function] for this acceptance criterion: [paste it].
Constraints: Don't rewrite my code. List up to 5 issues, most important first: bugs, edge cases I missed (empty list, reload, very long text), and anything confusing. For each, point to the line and explain why in one sentence. If nothing important is wrong, say "looks good".
Done when: I know what to fix and why.

    If #changes isn't offered, select your new lines in the editor and ask about "the selected code".

  7. Fix what you agree with, yourself. You may disagree with the review; write down why.

  8. Commit and push. For example Add item count (AC9), written by hand. If you changed something because of Copilot's review, add Assisted-by: GitHub Copilot as a second paragraph. In PROMPTS.md, finish the entry: the review prompt, which points you accepted or rejected, and which lines you wrote.

✅ Checkpoint: the new criterion passes in your preview, npm test is green, the commit is on GitHub, and PROMPTS.md says which lines you wrote. Card A and B tests count toward your three.

Card A — Show a count ​

Criterion: WHEN the list changes, THE APP SHALL show how many items there are above the list, for example "3 plants" (and "1 plant" for one), and WHEN there are none, SHALL show "Nothing here yet. Add your first one above."

Function: countLabel(count, singular, plural) in lib/count.js. It returns the text to show, and it's pure.

CallReturns
countLabel(3, "plant", "plants")"3 plants"
countLabel(1, "plant", "plants")"1 plant"
countLabel(0, "plant", "plants")"Nothing here yet. Add your first one above."

Connect it: add <p id="item-count"></p> above the list in index.html, import countLabel in app.js, and on the last line of your draw function, put the label into that paragraph's textContent.

Manual check: add two items → "2 plants"; delete one → "1 plant"; reload → still "1 plant"; delete the last one → the empty message.

Hint: a skeleton with blanks
js
// lib/count.js
export function countLabel(count, singular, plural) {
  if (count === ______) {
    return "______";
  }
  const word = count === 1 ? ______ : ______;
  return `${count} ${word}`; // a template literal, like a Python f-string
}
js
// the last line of your draw function, in app.js
document.getElementById("______").textContent = countLabel(______.length, "______", "______");

Card B — No duplicates ​

Criterion: WHEN I add an entry that matches one already on the list, ignoring capital letters and spaces at either end, THE APP SHALL not add it and SHALL show "That's already on your list."

Function: isDuplicate(text, existing) in lib/duplicates.js. text is what the user typed; existing is an array of the texts already on the list. It returns true or false, and it's pure.

CallReturns
isDuplicate("basil", ["Basil", "Mint"])true
isDuplicate(" Mint ", ["Basil", "Mint"])true
isDuplicate("Basil plant", ["Basil"])false
isDuplicate("Basil", [])false

Connect it: in the function that adds an item, before it adds anything, call isDuplicate(input.value, items.map((item) => item.name)); if it's true, show the message and return. Use your own names: .map builds a new array, like the Python list comprehension [item["name"] for item in items].

Manual check: add "Basil"; add " basil " → the message, nothing added; add "Basil plant" → added; reload, add "BASIL" → the message.

Hint: a skeleton with blanks
js
// lib/duplicates.js
export function isDuplicate(text, existing) {
  const wanted = text.______().______(); // spaces off the ends, then lowercase
  return existing.some((entry) => ______ === wanted); // .some is like Python's any()
}

Card C — Clear all, with a confirm ​

Criterion: WHEN I press Clear all and confirm, THE APP SHALL remove every item, and the list SHALL still be empty after a reload; WHEN I press Cancel, THE APP SHALL change nothing.

Function: clearAll() in app.js. It isn't pure (it asks the user, changes storage and redraws the page), so its check is the manual test you wrote first. It asks "Delete every item? This can't be undone." with confirm(...). On Cancel it returns without changing anything; on OK it empties your list, saves it and draws it again. Connect it to a new button:

html
<button id="clear-all" type="button">Clear all</button>

Manual check: add three items → Clear all → Cancel → all three still there; Clear all → OK → empty; reload → still empty.

Hint: a skeleton with blanks
js
function clearAll() {
  if (!confirm("______")) {
    return; // Cancel pressed: change nothing
  }
  ______ = []; // empty your list variable
  localStorage.setItem("______", JSON.stringify(______)); // your key, your list
  ______(); // your draw function
}

document.getElementById("______").addEventListener("______", clearAll);

TIP

TypeError: Assignment to constant variable? Your list is declared with const. Change that one word to let, and say why in your commit message. If your app already has a function that saves, call it instead of writing the setItem line.

If time: make your own card. Pick another small feature from your spec (a SHOULD story, or a MUST that's still failing). Ask Copilot in Ask mode for a short spec in the cards' format, with no code: the criterion, a function name, its inputs and output, and three examples. Then write the tests and the function yourself.

Part B2 — Project work time (25 min) ​

🟢 AI on, with Copilot in Ask mode or your chat assistant. No agent mode yet. Your instructor comes round to help: ask about whatever is blocking your Project 1.

In this order:

  1. Bring Part A2 up to at least three tests of your own logic.
  2. Fix the MUST criteria that still fail, with the Safe Loop: check first (a test, where the logic allows it), one step, test in the preview, read the diff, a teach-back in PROMPTS.md, commit.
  3. Bring TESTS.md up to date (homework finishes it).

Exit ticket (10 min) ​

The week 8 exit ticket: 🔴 AI off, graded on completion, not correctness. One question asks about your Project 1 v1 from week 6, from memory. Stop your Codespace before you leave.

Troubleshooting ​

ProblemTry this
The codespace won't start, or says you're out of hoursStop any other codespaces at github.com/codespaces, then see GitHub Codespaces
git show or git log fills the screen and won't go awayPress q
A git command opened an editor in the terminalYou left out --no-edit. If it's a VS Code tab, close it. If it's the Vim editor in the terminal, type :wq and press Enter
git push is rejectedSomeone (maybe you, on github.com) changed the repository. Run git pull, then git push again. Ask for help if you see "conflict"
npm test says it cannot find a module you createdCheck the folder (lib, at the top level) and the spelling of both the file name and the import line, including .js and the leading ./ or ../
npm test shows tests 0Node didn't find your test file. Its name must end in .test.js
npm test complains about JSONA comma or quote is missing in package.json. Compare it with the lab, character by character
A warning or error about modules or importCheck that package.json is in the top folder and has "type": "module", and that index.html loads app.js with type="module"
A test fails with two arrays that look the sameUse assert.deepEqual, not assert.equal
ReferenceError: document is not defined (or localStorage) in npm testThe function you're testing touches the page, and Node has no page. Pull the calculation out into its own function and pass in what it needs (Part A2, step 2)
After the module change, a button stopped workingYour HTML probably uses onclick="…". See the warning in Part A2, step 3
Copilot Chat has no Ask mode, or is out of creditsMenus change: look for a mode picker at the bottom of the chat box. Out of credits: use your chat assistant in a browser tab with the same prompts, pasting your diff (I ran out of free credits)
Files change by themselves while you writeThe chat is in Agent mode. Switch it to Ask. Discard the changes in Source Control, or git revert if they were committed

  • ☐ Your Project 1 is committed and pushed (Sync Changes or git push), including the revert, your tests and the function you wrote.
  • ☐ PROMPTS.md has the entry for your hand-written function (check, review prompt, what you wrote).
  • ☐ npm test passes.
  • ☐ Stop your codespaces: github.com/codespaces → … → Stop codespace. Stopped codespaces don't use your free hours.
