Week 8 — Own It ​

If you can't explain it, you didn't build it.

Learning objectives ​

By the end of this week you can:

  1. See your history and changes with git log, git show and git diff, throw away an uncommitted change with git restore, and undo a bad commit with git revert.
  2. Explain your own Project 1 out loud, with the AI off: a function, your save and load lines, and your history.
  3. Write a function yourself from a short spec, test first, and have Copilot's Ask mode review it.
  4. Choose what to test in your own app (the normal case, the boundaries, the empty case) and write automated tests for its pure logic with node --test.
  5. Show that each test can fail, by breaking the code on purpose.

Before class ​

  • ☐ Your week 7 fixes are committed and pushed, and your README's acceptance table is honest.
  • ☐ Read What to expect, and know when your walkthrough 1 slot is.
  • ☐ In your Project 1 Codespace, run npm test: it should run your week 6 test. No package.json yet? Lab Part A2 shows how to add one.
  • ☐ Copilot is on (accounts), with Chat: Disable AI Features unticked again after the clinic. The Copilot icon in the status bar shows this month's allowance: Ask mode uses some.

Key ideas ​

If you're working through this week on your own, read this section, then do the lab. The self-paced path says what to do instead of the walkthrough and the pair activities.

Your history is a debugging tool. git log --oneline lists your save points; git diff shows exactly what changed since the last one; git revert undoes a commit by adding a new commit, so nothing is lost. When something worked yesterday and doesn't today, the answer is in the history. Never use git reset --hard or git push --force to undo work: they delete history (Revert vs reset).

Own it: walkthrough 1. A 10-minute conversation with the AI off, on your own Project 1: explain a function, find the failing line after the examiner breaks one line, fix it, then commit and revert a change. The questions are published. It's not a trick test, and it can be retaken once.

You write it; the AI reviews. Copilot has three modes: inline suggestions (grey text as you type), Ask (a chat that answers without changing your files) and Agent (edits files and runs commands itself). This week uses Ask only, with suggestions switched off while you write. You get a short spec for one function (inputs, output, examples), write the tests from the examples, then write the function yourself. A skeleton with blanks is a hint if you're stuck, not the default. Then Copilot reviews your diff: you keep the thinking, and the AI helps you check it.

Test your own logic. In week 4 you wrote a first automated test with node --test, and in week 6 you checked first with one. Project 1 needs at least three, of its pure functions: functions that use only their inputs, with no document, no localStorage and no clock. Good tests come from your spec and your edge cases: the normal case, a boundary (exactly the limit, one over), and the empty case. Two habits make tests trustworthy:

  • See every test fail once. Break the function on purpose and watch the right test go red. A test you've never seen fail may not be checking anything (red/green testing).
  • Write tests apart from the code. When an AI writes tests after faulty code, the tests tend to agree with the faults: in a 2026 study they caught 14% of faults, against 25% for tests written independently (Konstantinou et al.; check first). Never change a test just to make it pass.

One JavaScript trap: [1, 2] === [1, 2] is false, because === asks whether they're the same array, while Python's [1, 2] == [1, 2] is True. To compare arrays and objects by their contents, use assert.deepEqual.

Understanding check ​

  • Exit ticket (🔴 AI off, graded on completion, not correctness): week 8 questions. One question asks about your week 6 Project 1 v1, from memory.
  • Oral walkthrough 1 (10 minutes, 🔴 AI off, on your own Project 1), in either studio this week or in office hours. The questions are in the Walkthrough 1 section of the oral walkthroughs page.

To check yourself first: open one of your tests, say what it checks, and name a change that would make it fail. Then explain the difference between git restore and git revert.

If a tool is down ​

If this failsDo this
Codespaces won't start or you're out of free hoursStop your other codespaces at github.com/codespaces. Otherwise use local setup, or pair with a partner in their codespace. A walkthrough can run from local setup, or be rescheduled without penalty
Copilot is unavailable or out of creditsUse your chat assistant in a browser tab, pasting the diff you want reviewed (Tool Handout)
npm isn't found or Node is too oldIn a Codespace it's preinstalled. Elsewhere you need Node.js 22 LTS (minimum 20.12): troubleshooting
GitHub Pages is slow to updateCheck the Actions tab
