Week 3 — Prompting & Save Points ​

A clear prompt tells the AI where to go; a commit makes sure you can always get back.

Learning objectives ​

By the end of this week you can:

  1. Write a prompt in four parts, Goal · Context · Constraints · Done when, and say why each part is there.
  2. Decide what to paste into a prompt, knowing the AI sees only its context.
  3. Ask for a plan before any code, and improve it.
  4. Build in small steps, and explain why one giant prompt produces code that is hard to change.
  5. Use the two-strikes rule when a fix isn't working.
  6. In github.dev, commit with clear messages, read a diff, and find a file's history and a commit's hash.
  7. Explain what git revert does and why it keeps the history.
  8. Mark AI-helped commits with an Assisted-by: line.

Before class ​

  • ☐ Your home page is live at https://[your-username].github.io, with a Projects section that links to game/. If not, finish week 2 first, or ask for help.
  • ☐ You can sign in to a chat assistant with a live preview (Gemini Canvas, or Claude Artifacts if you're 18+). Next week you need a second one from the Tool Handout.
  • ☐ Read the six steps of the Safe Loop (10 minutes; the rest of the page is for later).
  • ☐ Skim the game menu and pick two games. New to JavaScript or the web? Pick a ★ Easy game.

Key ideas ​

If you are working through this week on your own, read this section, then do the lab. The self-paced path says what to do instead of the pair activities.

A prompt is a set of directions ​

A prompt is a work order for someone who can't ask you questions (unless you invite it to: the first of the three habits). Write it in four parts:

PartQuestion it answersExample
GoalWhat do I want?Make the snake speed up as it grows.
ContextWhat does the AI need to know?Here is my current game/index.html: …
ConstraintsWhat are the rules?Change only the speed. Give me the complete file.
Done whenHow will we both check?After every 5 foods, the snake is visibly faster.

"Done when" is the part people skip, and the most useful one: it turns "looks fine" into something you can test, like a program's expected output.

The AI only knows what's in its context ​

The model can't see your screen, your files or your repository, and a new chat starts empty. So paste what it needs: the current file, the exact error message, what you expected and what happened.

Small steps, and two strikes ​

In a study of 33 learners using an AI code generator, those who generated a whole solution from one prompt did best on the first try, and worst when they later had to change their code (Kazemitabaar et al., Koli Calling 2023). Code always needs changing later, so build it in steps you can test and understand: ask for a plan first, edit it, then build one step at a time. The homework lets you try both on your own game. And when two attempts to fix the same problem fail, use the two-strikes rule: stop, go back to your last working version, and start a fresh chat with a better prompt.

Commits are save points ​

Git tracks every version of your repository (a project folder), and GitHub stores it online. A commit is a save point with a message and a hash (an ID like 4f2a9c1); the history lists them all. A diff shows what changed: removed lines in red, added in green.

To undo a bad change, you don't delete it: you make a new commit that puts the file back, so the history keeps both the mistake and the fix. That's what git revert does (revert). You'll restore your game by hand next week, and type the real command in week 8.

This week you commit in github.dev: press . (period) on your repository page and VS Code opens in your browser. It edits and commits, but can't run programs.

Saying when AI helped: the Assisted-by: line ​

Open-source projects such as LLVM and Fedora ask for a line like Assisted-by: Gemini at the end of a commit message when an AI tool helped (All Things Open). It tells readers which changes to check most carefully. Practice it from now; it's required from week 11.

Game in an Hour is graded on effort ​

The timer is real, but Game in an Hour is graded on effort, like every studio (rubric): a game that stops at step 3 with clean save points is a full-credit hour. Anyone may do it untimed (Timed builds).

Understanding check ​

  • At the end of Studio A: the Week 3 exit ticket (🔴 AI off, scored for completion). Expect: rewrite a weak prompt in four parts; what a diff shows; how to get back to an earlier version, and what happens to the bad commit; one question about your week 1 page.
  • In Studio B: the play-test. Someone plays your game for two minutes without help, and you watch where they get stuck.

Homework ​

About 5 hours of core work plus the journal; details on the homework page. Project time: finish the game, a commit for each working step. Homework: play-test and fix, link the game by hand, read three of your own diffs (🔴 AI off), the giant-prompt experiment, and Simon Willison's "Not all AI-assisted programming is vibe coding". Journal: PROMPTS.md; the reflection on Canvas (🔴 AI off). Stretch: a ★★★ game, or the study behind "small steps".

Graded on effort and completion of the core tier (rubric).

If a tool is down ​

ProblemWhat to do
Your main assistant is down or you hit a limitSwitch to a fallback from the Tool Handout and paste your current game/index.html from GitHub. See I ran out of free credits
No assistant has a live previewCommit each step and test it on your live site a minute later
github.dev won't openEdit and commit on github.com with the pencil icon (Add file → Create new file for new files)
GitHub is downBuild in the chat preview, save the code in a text file after each working step, and commit the steps later
