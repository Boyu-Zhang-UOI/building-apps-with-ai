Week 3 Lab — Save Points and Game in an Hour ​

Goal: in Studio A, set up your game file and practice the save-point workflow once, slowly: a four-part prompt, a diff, a commit with an Assisted-by: line, your History. In Studio B, build a small browser game in one timed hour, one step at a time, with a save point after every working step. Time: Studio A lab about 30 minutes, Studio B lab about 70 minutes. You need: your [your-username].github.io repository from week 2, a chat assistant with a live preview (see the Tool Handout), and the game menu.

AI-use key: 🟢 AI on: use AI freely · 🟡 AI limited: the AI may comment or hint, but the work is yours · 🔴 AI off: close the AI tabs and work alone.

Studios are graded on effort, not polish (rubric): a part that didn't work, with the exact error and what you tried, still counts.

This week you use the full Safe Loop for the first time: Describe → Plan → Step → Test → Read → Commit.

Stuck for more than 5 minutes? Check Troubleshooting, ask a neighbor, then raise your hand. Using a screen reader or only a keyboard? The Screen reader and keyboard guide covers github.dev and the GitHub website.

Words you'll use this week ​

WordMeaning
Repository (repo)A project folder that git tracks. Yours is [your-username].github.io
CommitA save point: a snapshot of your files, with a message saying what changed
Commit messageThe description of a commit, e.g. Step 2: snake moves with arrow keys
HistoryThe list of all commits, newest first
DiffWhat changed between two versions: removed lines in red (marked -), added lines in green (marked +)
HashA commit's ID, such as 4f2a9c1 (the short version is 7 characters)
github.devA code editor (VS Code) that runs in your browser and edits your repository directly. It can't run programs
Assisted-by: lineA last line in a commit message naming the AI tool that helped, e.g. Assisted-by: Gemini

More in the Git Cheat Sheet and the Glossary.

Studio A — Save points (75 min) ​

The studio opens with a recap, the concept talk and a live demo (30 minutes), then:

A2One small change, one save point15 minCore🟢 AI on · you write the prompt

The studio ends with a checkpoint share and the Week 3 exit ticket (🔴 AI off). The exit ticket is here, not in Studio B, because the game fills Studio B.

Part A1 — Open github.dev and create your game file (10 min) ​

Why: chat assistants forget and previews disappear. Your repository keeps every version you commit.

  1. Open your repository on github.com: https://github.com/[your-username]/[your-username].github.io.

  2. Press the . (period) key, with the cursor not in a text box. github.dev opens: a code editor in your browser. (Or change github.com to github.dev in the address bar.) Sign in if asked.

  3. In the Explorer panel on the left, hover over your repository's name and click the New File icon. Type game/index.html and press Enter. The / creates a folder called game.

  4. Type this placeholder by hand:

    html
    <!DOCTYPE html>
<title>My game</title>
<h1>Game coming soon</h1>

  5. Save with Ctrl+S (Windows, ChromeOS) or Cmd+S (Mac).

  6. Open Source Control: the icon of three connected dots in the left bar, or Ctrl+Shift+G (on a Mac, Control+Shift+G). Your file appears under Changes. Click it to see the diff: every line is green because it's new.

  7. In the Message box, type Add game placeholder. Click Commit & Push. If github.dev asks whether to stage all changes and commit them directly, choose Yes.

  8. Wait a minute, then visit https://[your-username].github.io/game/.

NOTE

Menus move. If a button has a different name, look for the same idea (a message box and a commit button), or ask your assistant where it is in github.dev today.

✅ Checkpoint: https://[your-username].github.io/game/ shows "Game coming soon", and the Projects link on your home page now leads there instead of a 404.

Part A2 — One small change, one save point (15 min) ​

🟢 AI on. You write the prompt yourself; the AI writes the code.

Why: you'll make about ten commits in Studio B's hour, against the clock. Do the whole loop once now, slowly, while nothing is at stake.

  1. Describe. Pick one small change to your home page, for example a footer line "Last updated [month year]", links that change color when you hover over them, or a "Back to top" link. In your scratch note, write a four-part prompt for it:

    text
    Goal: [one small change].
Context: Here is my current index.html: [paste the complete file].
Constraints: Change only what this needs and keep everything else exactly as it is. Give me the complete updated file in one code block.
Done when: [what you'll see on the page, checkable in under a minute].

    To get the complete file, open index.html on github.com and click Copy raw file (two overlapping squares, top right of the code).

  2. Step and Test. Send it to your assistant. In the preview, check your "Done when", and check that the rest of the page still looks the same.

  3. Read. Copy the complete file. In github.dev, click into index.html, select everything (Ctrl+A / Cmd+A), paste and save. In Source Control, click the file to see the diff. Does the size of the change match the size of what you asked for? If the AI changed something you didn't ask for, ask it why before you commit.

  4. Commit, with an Assisted-by: line. The first line says what changed, as always. Then a blank line. Then the tool:

    text
    Add "Last updated" line to the footer

Assisted-by: Gemini

    In github.dev's Message box, type the first line, press Enter twice to add a blank line, then type Assisted-by: [tool]. (Ctrl+Enter / Cmd+Enter commits; plain Enter adds a new line.) Then Commit & Push. On github.com (pencil icon), the first line goes in Commit message and Assisted-by: [tool] in Extended description.

Use the Assisted-by: line when an AI wrote or shaped the change; if you used two tools, add one line for each. Leave it off for changes you made entirely by hand. More in the Safe Loop's Assisted-by section.

✅ Checkpoint: your live home page shows the change a minute later, and the commit's message ends with Assisted-by: [tool].

Part A3 — Read your History (5 min) ​

  1. On github.com, open your repository, then index.html, and click History (top right of the file, with a clock icon). You'll see every commit that changed this file, newest first.
  2. Click your commit from Part A2. Read the red and green lines. Check that the Assisted-by: line is there, under the message.
  3. Find the commit's short hash (like 4f2a9c1) and copy it into your scratch note, with the commit's link.

Every row in this list can be brought back. To undo a bad change, you don't delete its commit: you add a new commit that puts the file back the way it was, so the history keeps both. That's what git revert does. Next week you'll break your game on purpose and do exactly that.

✅ Checkpoint: you have the link to your Assisted-by: commit and its hash in your scratch note.

Part A4 — Get ready for Game in an Hour (5 min, if time) ​

  • Pick your game and a backup from the game menu. Read its sample plan and its "Watch out for" line.
  • Start a new scratch note for Studio B, titled with your game's name, so you're ready to paste a plan into it.
  • Check that your preview assistant is signed in and has its live preview on.

Checkpoint share and exit ticket (end of Studio A) ​

Post the link to your Assisted-by: commit where your instructor asks, with the game you picked (for example "Snake, link: …"). Stuck? Post the exact blocker instead: that counts too.

Then do the Week 3 exit ticket (10 min, 🔴 AI off). It's scored for completion, not correctness.

Working alone? Write the link and your game choice in your scratch note.

Studio B — Game in an Hour (75 min) ​

B2Game in an Hour (timed)60 minCore🟢 AI on

Part B1 — Ready check (5 min) ​

Before the timer starts, have three tabs open: github.dev on your repository with game/index.html open, your assistant in a new chat with the live preview available, and the game menu. Keep your scratch note beside them.

Your instructor starts a visible 60-minute timer. Working alone? Set one on your phone. Rather work without the clock (for example with a screen reader)? Anyone may do it untimed; see Timed builds for tips and game choices.

Part B2 — Game in an Hour (60 min, timed) ​

🟢 AI on.

The goal is a working game built in small steps, not a perfect game. Game in an Hour is graded on effort, not on whether you finish (rubric). A game that stops at step 3 with clean save points beats a broken five-step game, and it's a full-credit hour.

MinutesStage
0–8Pick a game and plan it
8–25Steps 1 and 2
25–40Step 3
40–52Step 4
52–60Step 5, or polish

Pick a game and plan it (minutes 0–8) ​

  1. Choose a game from the game menu. New to JavaScript or the web? Pick a ★ Easy game.

  2. In an assistant with a live preview (Gemini with Canvas, or Claude with Artifacts), start a new chat.

  3. Describe and Plan. Send this, filling in the brackets:

    text
    Goal: Build a [game name] game that runs in the browser: [one-sentence description from the game menu].
Context: I know some programming ([your language]) but I'm new to JavaScript and the web. I'll build it in small steps and save a working version after each step. It will live at game/index.html on my GitHub Pages site.
Constraints: One HTML file with the CSS and JavaScript inside it. No libraries, no external images, sounds or fonts. Playable with a keyboard or mouse on a laptop. Don't write any code yet.
Done when: You have proposed a plan of exactly 5 small steps. Each step adds one visible feature, can be tested in under a minute, and ends with a "Done when" line I can check. Step 1 is only the layout, with nothing moving yet.

  4. Edit the plan. Compare it with the sample plan in the game menu. Is step 1 small? Can you test every step in a minute? Is anything too big (online leaderboards, multiplayer, accounts)? Tell the AI what to change, for example: Split step 2 into two steps and drop the sound effects. Show me the final plan. Still no code.

  5. Copy the final plan into your scratch note. You'll paste each step into the prompts below, and the plan into PROMPTS.md later.

✅ Checkpoint: you have a 5-step plan, with a "Done when" for every step, that you changed at least once.

The loop for every step (minutes 8–60) ​

Repeat this for steps 1 to 5.

Step. Send one step:

text
Goal: Do step [N] of the plan: [paste the step].
Context: [For step 1: "We're starting from an empty file." Later: "Here is my current game/index.html:" then paste the complete file.]
Constraints: Change only what this step needs and keep everything that already works. Give me the complete updated file in one code block, not just the changed part.
Done when: [paste the step's "Done when" line].

TIP

Why paste the file each time? The AI only knows what is in its context window. It can't see your repository, and it doesn't know about changes you made elsewhere. If you're in the same chat and haven't changed anything, "Context: the file from your last answer" is fine.

Test. In the preview, check the "Done when" line. Then try one edge case, a less common situation: click twice quickly, press a key that isn't a control, make the window narrow.

  • It works: go on to Read.
  • It doesn't: say exactly what happened: After this step, [what I did]. I expected [X]. Instead [Y]. Fix only that, and give me the complete file.
  • Two failed fixes? That's the two-strikes rule: stop, start a fresh chat, paste your last working file from GitHub, and describe the problem more precisely.

Read. Copy the complete file. In github.dev, click into game/index.html, select everything (Ctrl+A / Cmd+A), paste, and save. Open Source Control and click the file to see the diff. Skim the red and green lines. Does the size of the change match the size of the step? If the AI changed something you didn't ask for, ask it why before you commit.

Commit. Type a message that says what changed, a blank line and Assisted-by: [tool], then Commit & Push:

Good messagesBad messages
Step 1: draw the board, snake and foodupdate
Step 2: snake moves with arrow keysstuff
Fix: arrow keys no longer scroll the pagefixed it!!!

After a minute, https://[your-username].github.io/game/ shows the new version. You don't need to wait for it; keep going.

✅ Checkpoint (by minute 25): github.dev's Source Control shows no pending changes, and you've made two commits, Step 1: … and Step 2: ….

✅ Checkpoint (at the buzzer): your last commit is a working version. If your current step is half-done and broken, don't commit it. Your game at /game/ works up to at least step 2 or 3, with one commit per working step.

Part B3 — Play-test swap and checkpoint share (10 min) ​

  1. Swap links with a neighbor. Play each other's game for two minutes without help. Watch them play yours, and write down the first thing that confused them. Don't fix it now: it's the first job in your homework.
  2. Post your game's live URL where your instructor asks, with the number of working-step commits in its History (for example "Snake, 4 save points"). Stuck? Post the exact blocker instead: that counts too.

Working alone? Play your own game for two minutes, trying to break it, and ask someone at home to try it later this week. Write the URL and the count in your scratch note.

Before you leave Studio B ​

  • ☐ Your game works at https://[your-username].github.io/game/, at least up to step 2 or 3.
  • ☐ Its History shows one commit per working step, with clear messages.
  • ☐ Your scratch note has the plan, what confused your play-tester, and anything you'd prompt differently. You'll need them for PROMPTS.md.

Troubleshooting ​

ProblemFix
Pressing . does nothingClick an empty part of the page first (not a text box), or change github.com to github.dev in the address bar
Commit & Push is greyed outType a commit message, and save the file first (Ctrl+S / Cmd+S)
The Assisted-by: line doesn't show in the commit on github.comIt must be part of the commit message: in github.dev, on its own line after a blank line; on github.com, in Extended description. Add it to your next AI-helped commit; don't redo old ones
The game is blank after pastingYou pasted only part of the code, or chat formatting (``` lines). Ask for "the complete file in one code block" and use the copy button
The AI gives snippets ("add this inside your update function")Reply: Give me the complete updated file in one code block.
Arrow keys or Space scroll the pageAsk: Stop the game's keys from scrolling the page. Complete file, please.
Works in the preview, not on the live siteWait a minute and hard-refresh (Ctrl+Shift+R / Cmd+Shift+R). Check the path is exactly game/index.html, lowercase, and the address ends in /game/
Can't find HistoryOpen the file itself first (not the folder), then look at the top right of the code
github.dev says it can't push or there's a conflictCopy your current code into a note, close github.dev, reopen it, and paste your change again
You hit an assistant's usage limitSwitch to another assistant and paste your current file from GitHub. See I ran out of free credits
You're stuck on step 1 after 15 minutesSwitch to a ★ Easy game from the menu and use its sample plan as your plan. Tell your instructor

If a tool is down ​

  • Main assistant down: use a fallback from the Tool Handout. Paste your current game/index.html from GitHub into the new chat first, because the new tool starts with an empty context window.
  • No assistant with a preview: commit each step and test it on your live site a minute later.
  • github.dev won't open: edit on github.com instead. Open the file, click the pencil icon, paste, then Commit changes… (the Assisted-by: line goes in Extended description). To create game/index.html, use Add file → Create new file and type game/index.html as the name.
