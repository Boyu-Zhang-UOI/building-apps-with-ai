Week 7 — Read It, Debug It ​

You must be able to read and fix what the AI wrote.

Learning objectives ​

By the end of this week you can:

  1. Name the parts of a small web app (structure, style, behavior, state, storage) and find each one in your own files.
  2. Read a browser error message and a stack trace, and go to the failing line.
  3. Debug with a method (reproduce → isolate → hypothesize → test → fix → verify) instead of pasting errors into a chat.
  4. Explain why input.value is text, and how JSON.stringify and JSON.parse save and load data in localStorage.
  5. Find the edge cases where your own app breaks, and write them down as tests.

Before class ​

  • ☐ Your Project 1 version 1 is live on GitHub Pages (week 6 homework).
  • ☐ Stop any codespaces you aren't using at github.com/codespaces. You'll run two in Studio A: your Project 1 and the clinic.
  • ☐ Read "HTML, CSS and JavaScript" and "A short DevTools tour" in How the Web Works.
  • ☐ In your own app.js, find one getElementById, one addEventListener and the localStorage.setItem line.

Key ideas ​

If you're working through this week on your own, read this section, then do the lab. The self-paced path says what to do instead of the pair activities.

Why this week exists. AI helps people finish tasks, but it can stop them learning to debug. In Anthropic's January 2026 randomized trial, junior engineers who learned a new library with an AI assistant scored 50% on a follow-up quiz, against 67% without it, and the biggest gap was on debugging (Anthropic). In a 2026 study of 78 learners, 77% of those who had used AI without limits failed a 30-minute maintenance task once the AI was switched off (Sankaranarayanan). In CMU's AI coding course, understanding peaked on the assignment where students read and partly wrote the code (CMU 15-113). So this week you read and debug, and next week you write, before agents arrive in week 11.

Anatomy of a web app. Every app you've built so far has five parts. Structure: HTML elements such as <button> and <ul>, each of which can have an id, a unique name JavaScript uses to find it. JavaScript sees the page as the DOM (Document Object Model), a live model of the HTML it can read and change. Style: CSS, which rarely crashes but can look wrong. Behavior: JavaScript functions connected to events (clicks, typing) with addEventListener. State: the data the app is holding right now, in variables, lost on reload. Storage: localStorage keeps text only, so data goes in with JSON.stringify and comes back out with JSON.parse (like Python's json.dumps and json.loads). And whatever a user types arrives as text, even in a number box. Python would stop you with a TypeError; JavaScript quietly joins the two: 40 + "5" is "405".

Read the error before you paste it. Browser DevTools (F12) has a Console that shows errors in red and warnings in yellow. An error has a type (SyntaxError: the file couldn't be read; TypeError: a value wasn't what the code expected; ReferenceError: a name doesn't exist), a message, and a file and line number you can click. A stack trace lists the chain of function calls. It's upside down compared with a Python traceback: the top line is where it broke, and the lines below are who called it.

The debugging method. Reproduce (make it happen on purpose), isolate (which file, function and line?), hypothesize (say what you think is wrong and why), test the idea before changing code (type a variable name in the Console, or add console.log), fix the cause with the smallest change, and verify (repeat the steps and check nothing else broke).

Bugs live at the edges. The normal case usually works, because it's the case the AI was thinking about. Edge cases are the unusual-but-possible ones: empty input, huge input, duplicates, special characters, reloading, a small screen, a first visit with nothing saved. When researchers watched students build with an AI agent, only 2.2% of their checks tried one (Geng et al.).

Understanding check ​

  • Exit ticket (🔴 AI off, end of Studio A, graded on completion, not correctness): week 7 questions. One question asks about your week 5 spec, from memory.
  • The error drill and the Debug Clinic (🔴 AI off) are practice for the first of the six skills you must show without AI: reading an error message and finding the failing line.

To check yourself first: open your app.js, point to the line that saves your data and the line that loads it, and explain each in one sentence. Then explain what Cannot read properties of null means and where you'd look first.

Homework ​

About 5¼ hours, including project time: the clinic's five bugs in your own code (🔴 AI off to check), an edge-case hunt recorded in TESTS.md, fixes for failing MUST criteria, a "How it works" draft, and a reflection on Canvas. Details: homework.
