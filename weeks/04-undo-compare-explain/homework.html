Week 4 Homework ​

Due before next week's Studio A (default 11:59 pm the night before). Core: about 5 hours plus the journal, required. Stretch: optional. Graded on effort and completion of the core tier (rubric). "On Canvas" means the course's learning management system, not Gemini's Canvas tool.

Use the Safe Loop for every change: Describe → Plan → Step → Test → Read → Commit.

Deliverables checklist ​

  • ☐ My game has one more feature, with its "Done when" written first, built in at least three commits, each with a teach-back in PROMPTS.md and an Assisted-by: line (task 1).
  • ☐ My game's History shows the Studio A break and restore, and my restore drill (task 2).
  • ☐ prompt-makeover.md in my home-page repository has my four rewrites (🔴 AI off) and the result of testing one (task 3).
  • ☐ My game uses the function in game/logic.js, and npm test passes, including my own test (task 4).
  • ☐ PROMPTS.md has this week's entries (task 5).
  • ☐ On Canvas: my weekly reflection (🔴 AI off) (task 6).

Core ​

1. One more feature in three save points (2 h) ​

🟢 AI on · 🔴 AI off for your "Done when" and your teach-backs.

Add one feature your game doesn't have yet. Ideas:

  • A high score that survives a reload, in localStorage: a small storage space the browser keeps for your site on this device only.
  • Sound effects, generated in code (the browser's Web Audio API, no sound files), with a mute button.
  • Touch controls so the game works on your phone.
  • A second level that starts when level 1 is won.
  • Pause and resume, or a difficulty setting.
  1. Check first. Before you ask the AI anything, write the feature's "Done when" in PROMPTS.md yourself, as things you'll try by hand (you may have started in Part A3).
  2. Plan. Ask for three small steps, each with a "Done when", pasting your complete file. Edit the plan until it meets your "Done when".
  3. Build each step with the Safe Loop: step prompt, test, read the diff.
  4. Teach back before each commit (🔴 AI off): 2–3 sentences in PROMPTS.md on what changed, why it works, and what you'd check first if it broke. Can't write it? Ask the AI to explain the diff, read it again, then write it yourself.
  5. Commit each working step with an Assisted-by: line.

✅ Checkpoint: the feature meets the "Done when" you wrote first, in at least three commits, each with a teach-back in PROMPTS.md.

2. Restore drill (30 min) ​

🔴 AI off.

Going back to a working version is one of the six skills you must show without AI, and your first oral walkthrough (week 8) asks for it. Practice once more, without the lab open: break your game or home page by hand (delete a > or a }) and commit it as Experiment: restore drill; restore the last working version from History as Restore working version from [hash]; check the live page; close and reopen github.dev. In PROMPTS.md, note the hash and any step you had to look up.

3. Prompt makeover (1 h) ​

🔴 AI off for the rewrites · 🟢 AI on for testing one.

  1. Create prompt-makeover.md in your home-page repository, with your rewrite of prompt A from Part B3, improved with your neighbor's suggestion.
  2. Rewrite B, C and D in four parts, yourself, without AI, and check each against Part B3's four questions.
  3. Test one (🟢 AI on): send it to an assistant, and say in two sentences under it whether the result met your "Done when" and what you'd change next time. Commit.

4. Make your game use the tested function (1 h 15 min) ​

🟡 AI limited: the AI may explain an error; you make the changes.

In Studio B you tested a copy of your function in game/logic.js. Now make the game use that file, so the code you tested is the code that runs.

  1. Fix what your own test found (lab Part B2, step 7), if it failed: decide the right answer, change logic.js, and run npm test until it's green. If you decide the test was wrong instead, say why in PROMPTS.md.

  2. In a Codespace (or on your own computer), open game/index.html. Change the game's <script> tag to <script type="module">, and add this as the first line inside it, with your function's name:

    js
    import { averageTime } from "./logic.js";

  3. Delete the old copy of the function from index.html, so there's only one.

  4. Test the game by hand. In the terminal, run python3 -m http.server 8000, open the forwarded port, and go to /game/ (add game/ to the end of the address). Play it through; check the browser's Console for red errors. Stop the server with Ctrl+C.

  5. Run npm test once more, then commit and push: Use tested [function] from logic.js.

WARNING

Three things change when the game's script becomes a module. (1) onclick="startGame()" in your HTML stops working, because a module's functions aren't global: switch to addEventListener, or ask the AI to explain how. (2) A module only works when the page is served (a Codespace preview or GitHub Pages), not opened from your computer's files, and a chat preview can't see logic.js. (3) If the game breaks and two fixes fail, that's the two-strikes rule: restore the last working version from History, and ask for help in office hours.

✅ Checkpoint: your live game works and uses game/logic.js, and npm test passes.

5. PROMPTS.md (15 min) ​

🟢 AI on for formatting · 🔴 AI off for "What I wrote or decided myself" and the teach-backs.

Add a Week 4 heading, with the prompts written in four-part form (Goal · Context · Constraints · Done when):

  • the Studio A restore and your restore drill, with the hashes;
  • your model comparison: your "Done when", the table from Part A2, and the winner;
  • anything from the peer swap you looked up afterwards;
  • your first test: the function, and your own test's prediction and result;
  • your feature: its "Done when", the plan, and a teach-back for each commit.

Update What I wrote or decided myself (your tests, your restore, the rewrites) and What I'd prompt differently next time. Commit with a clear message.

6. Weekly reflection (20 min) ​

🔴 AI off.

Answer the four questions in the reflection template in 150–300 words, without AI. Good moments to write about: the second you broke your game on purpose, a difference between the two models' answers, explaining a classmate's function, or the first time a test went red. Submit it on Canvas, not in your repository (Privacy of your work).

Stretch (optional) ​

Each is a small Safe Loop: commit after each working step, and log your prompts in PROMPTS.md.

  • A test written first, for your feature. If your feature has a pure piece (such as isNewBest(score, best)), write its test in tests/logic.test.js, see it fail, then ask for the code. That's check first as it works from week 6; the check-first test prompt asks an AI for a test without showing it the code.
  • A second tested function, with an edge-case test, or a second feature from task 1.

IMPORTANT

Minimum to keep up: you can restore an earlier version of a file from its History, and npm test runs at least one passing test in your home-page repository. Week 5 starts a new project in a new repository with the same commit habits, and from week 6 its checks are automated tests like this one. If either isn't working, ask your instructor for help before Studio A.
