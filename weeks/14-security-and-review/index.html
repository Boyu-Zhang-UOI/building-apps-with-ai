Week 14 — Security & Review ​

Passing tests is not a security check. This week you sweep your capstone for the risks beyond the database, change it with the AI switched off, and let a classmate review it and try to change it.

Canvas is the course's learning management system. Graded personal writing (the written review, your response to the review you received, your reflection) goes there, never in a repo.

Learning objectives ​

By the end of this week you can:

  1. Find and fix cross-site scripting (XSS) in your own pages, and explain why textContent is safe where innerHTML isn't.
  2. Sweep your capstone for secrets in your files and git history, risky packages and CDN imports, and XSS, with one line of evidence each.
  3. Explain prompt injection and the lethal trifecta, and say which parts of it your own agent setup has.
  4. Write a one-paragraph threat model of one feature: who could misuse it, how, and what stops them.
  5. Change your own code with the AI switched off.
  6. Review a classmate's pull request as a human, compare it with an AI review, respond to the review you received, and hand your project off so someone else can change it.

Before class ​

Before Studio A (30 minutes at most):

  • ☐ Read this page, and case 15: Malware that hunts for AI keys.
  • ☐ Book your oral walkthrough 3 slot on Canvas: in this week's studios or an office-hour slot this week (what to expect).
  • ☐ Agree with your review partner (your instructor pairs you) which of your pull requests they'll review: your week-13 data feature is ideal, a week-12 one works too.
  • ☐ Commit and push everything, so git status shows nothing to commit. The maintenance task starts from a clean tree.

Key ideas ​

Passing tests is not a security check. Given 186 real vulnerabilities rewritten as feature requests, a frontier model wrote working code 93.5% of the time but working and secure code only 54.8% of the time (Semgrep). Last week you tested who can read and change your data. This week you check the rest.

Cross-site scripting. XSS happens when text a user typed is put on the page with innerHTML and runs as code in other visitors' browsers. Use textContent, which always shows text as text (innerHTML and textContent). If you've met SQL injection, it's the same mistake: data treated as code. In 2026 tests, only 15% of AI code samples defended against it (Veracode).

Secrets in old commits. Deleting a key from today's file doesn't remove it from git history, and anyone can read a public repo's history. The course's secret scan (npm run check:secrets) reads the whole history. A key found there must be revoked and replaced; rewriting history isn't enough.

Packages. Installing a package runs a stranger's code. Slopsquatting is when an attacker registers a name that AI models tend to invent (case 10). Real packages get hijacked too: in October 2026 a compromised npm release stole .env files and .claude and MCP settings on install, and a poisoned Python package stole AI provider keys (case 15). pip install runs code just like npm install. Install only what the plan named, check it's the one you meant, and pin the version.

No attacker needed. Helpful agents created public repositories that exposed more than 13,000 internal screenshots (PixelLeak, The Hacker News), and an agent used a token from an unrelated file to delete a production database and its backups in about nine seconds (PocketOS, Information Age). So agents don't publish without your approval, and keys stay out of their reach (safety contract, rules 4 and 9).

Prompt injection. Prompt injection is when text an agent reads (a file, a web page, an issue) gives it orders. The lethal trifecta is private data + untrusted content + a way to send data out (Willison); Meta's Rule of Two says an agent should hold at most two of them without a human approving (Meta). AGENTS.md can tell an agent to ignore such text, but it's advice, not a lock.

A threat model in one paragraph. Say what "unsafe" would mean before you check: who could misuse a feature, how, and what stops them. It's the short form of the questions professionals ask: what are we working on, what can go wrong, what are we going to do about it, and did we do a good enough job (Threat Modeling Manifesto).

Can you maintain it without the AI? In one study, 77% of students who used AI without restrictions failed a 30-minute maintenance task with the AI switched off, against 39% of those who had to explain the code first (Sankaranarayanan). Experience doesn't exempt you: experienced developers were 19% slower with AI while believing they were faster (case 11, METR). Studio B's maintenance task is graded on effort, not on finishing.

Humans and AI both review. An AI reviewer is fast and tireless, but it misses the goal and raises false alarms. A human reviewer knows what the app is for. You review a classmate's pull request yourself, then compare with an AI review. The handoff test asks the harder question: can someone else change your app from your README.md and AGENTS.md alone?

Understanding check ​

  • The week 14 exit ticket comes at the end of Studio A, with AI off (🔴), because Studio B is full of AI-off work. You'll explain prompt injection and what protects you, describe one vulnerability you found or fixed, and answer one question from memory about your week-12 pull request. Graded on completion, not correctness.
  • Oral walkthrough 3 (10 minutes, 🔴 AI off) runs this week, in a studio slot or an office-hour slot: explain where authorization is enforced, find and fix a planted bug, spot a committed secret in a sample diff, and explain one of your tests (what to expect). It's the last walkthrough: week 15 has none.

Homework ​

Homework: reach Milestone 2: the checklist and threat model, the written review and your response to the one you received, the handoff test, walkthrough 3 and your reflection. About 5.5 hours.

If a tool is down ​

  • Codespaces quota gone: do the maintenance task in github.dev and check it on your Vercel preview; run the sweep's commands with a local setup or in office hours. The review needs only the GitHub website.
  • Copilot credits gone: the review, the maintenance task and the sweep need no AI. For the AI half of the review, use any free chat assistant with the diff pasted in (I ran out of free credits).
  • npm audit says ENOLOCK: run npm install once and commit the package-lock.json it creates (lab Part A1).
  • No partner today: your instructor gives you a change-request card and a practice pull request with known issues to review (Self-paced path).
  • Your capstone is behind: sweep your week-9 micro-app instead; the maintenance cards are small enough for whatever your capstone has.
  • Missed your walkthrough slot for illness or another recognized reason? Tell your instructor: it's rescheduled without penalty.

Going further ​

  • Protect your main branch so it only accepts pull requests with a green test run (homework stretch).
  • Read one 2026 incident in full from Case Studies and add a one-line lesson to your SECURITY_CHECKLIST.md.
  • Try the Prompt-injection demo kit yourself in a fresh Codespace, never in your capstone.
  • Extend your threat model with STRIDE, the six-category checklist many teams use (OWASP Threat Modeling Cheat Sheet).
