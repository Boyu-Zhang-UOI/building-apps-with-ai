Week 2 — Ship Your Page ​

Publishing turns your page into something other people use, so it has to work for everyone, and you should be able to show how you made it.

Learning objectives ​

By the end of this week you can:

  1. Explain how a file becomes a web page at a URL, and why it's called index.html.
  2. Publish a page on GitHub Pages and update it with commits that have clear messages.
  3. Use the three habits: ask me questions first, show a reference, say what works.
  4. Check a page for basic accessibility problems (keyboard, zoom, contrast, structure) and fix them.
  5. Keep a PROMPTS.md log that separates what the AI did from what you did.
  6. Write your own rules for when you will and won't use AI.
  7. Connect two of the four AI fluency skills to your own work.

Before class ​

  • ☐ Finish the week 1 homework. Have your latest index.html on the laptop you bring (or download it from Canvas in class).
  • ☐ Check that you can sign in to github.com on that laptop. Bring your phone: GitHub asks for your second factor on a new browser.
  • ☐ Read this page (10 minutes). If the GitHub website is new to you, skim GitHub basics.

Key ideas ​

If you are working through this week on your own, read this section, then do the lab. The self-paced path says what to do instead of the pair and class activities.

From your screen to the world ​

GitHub stores your files in a repository (a project folder that git tracks), and GitHub Pages serves them as a website, for free. A repository named exactly [your-username].github.io becomes the site at that URL (web address). The file must be called index.html: that's what a web server sends for a site's front door. It's a static site: the server sends the same files to everyone and runs none of your code (servers that run code come in week 9).

A commit is a save point ​

Every time you add or edit a file on GitHub, you make a commit: a saved snapshot with a message saying what changed ("Add Projects section", not "update"). The repository keeps every commit, so you can see the history and get old versions back. In week 3 you learn git properly.

Public means public ​

Search engines find your page, and old commits stay visible after you delete something. First name or nickname only; no contact details, student ID or anything about other people. Graded personal writing goes on Canvas, never in a repository (Privacy of your work).

The three habits ​

Students in a Fall 2026 AI-coding course at Carnegie Mellon named these as their most useful practices (CMU 15-113 report). You practice all three in Studio B and use them for the rest of the course.

  1. Ask me questions first. Before the AI builds, have it ask you what it needs to know. Otherwise it fills the gaps with guesses.
  2. Show, don't describe. A quick sketch or a screenshot with the problem circled says more than a paragraph.
  3. Say what works before asking for a change. Name what must stay the same, so the AI doesn't "improve" it away.

Accessible from the start ​

Accessibility means people who use a screen reader, a keyboard, zoom or high contrast can use your page too. Most problems on a one-file page take a minute to fix: a missing lang attribute, a clickable <div> that should be a <button>, gray text on gray. You check keyboard, zoom, contrast and structure, ask the AI for a review, and confirm each problem it names yourself.

PROMPTS.md: how you used AI ​

Every project keeps a Glossary: PROMPTS.md log: the prompts that mattered, what happened, and what you checked. Its Ownership statement, written with the AI off, says what you wrote or decided yourself. With Gemini's Keep Activity off, a closed chat is gone, so copy prompts in as you go. The file is public: no keys, nothing personal.

Your own AI-use rules ​

The course's labels say where AI is allowed; inside them, you decide how you want to use it. Students who had written their own rules for using AI did better than those who hadn't (Azimi, 2026). You write version 1 in Studio B with the AI off, and revise it in week 16.

AI fluency ​

You finish the AI Fluency course this week. Its four skills are Delegation (what to hand to an AI), Description (saying clearly what you want), Discernment (judging what comes back) and Diligence (taking responsibility for the result). The three habits are Description and Discernment in practice.

Understanding check ​

At the end of Studio B you complete the Week 2 exit ticket with 🔴 AI off. One question asks you, from memory, about a change you made by hand in week 1: which part of the code, and what it did. The others ask how your file became a web page, which habit changed your result, and what your accessibility check found. It's scored for completion, not correctness.

Homework ​

About 5 hours, including project time; details on the homework page. Add a Projects section that will link to next week's game, plus three more improvements, one commit each, using each habit and one change by hand (🔴 AI off) · fix your accessibility list · finish the AI Fluency course and write a short response on Canvas (🔴 AI off) · PROMPTS.md with 5+ entries · a reflection on Canvas (🔴 AI off).

Graded on effort and completion of the core tier (rubric).

Gemini is down or blockedUse a fallback from the Tool Handout, and paste in your current code first
You hit a usage limitSwitch to the next tool in the row. See I ran out of free credits
