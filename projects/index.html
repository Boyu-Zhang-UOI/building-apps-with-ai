Projects ​

Five things you build and ship, in four repositories. Each one is live on the public web, and each one adds a habit the next one needs.

You will build a personal page, a game, a tool you actually use, a small AI-powered app and a capstone of your choice. Each project lives in its own GitHub repository (repo: a project folder that git tracks, stored on GitHub), and each is deployed (published so anyone with the link can use it). New words are explained in the glossary.

The three project rules ​

These apply to every project, including stretch work. They come from the safety contract.

  1. No real payments. Free hosting tiers forbid commercial use (Vercel Hobby; GitHub Pages), and payment code is high-stakes. A "Buy" button that does nothing real is fine for a demo.
  2. No real personal data about other people. Use made-up names, emails and entries. Free AI tiers may train on what you type, and a single missing database rule can make everything public.
  3. Nothing you would miss if an AI agent deleted it. Keep real documents, photos and work files out of your project folders. AI agents have deleted files and databases they were not supposed to touch (case studies).

If you are not sure whether an idea breaks a rule, ask before you build it.

What goes in a repo, and what goes on Canvas ​

Your project repos are public: they become your portfolio. Your grades and personal writing stay private, on Canvas.

  • In your repos: code, SPEC.md, TESTS.md, PROMPTS.md, AGENTS.md, SECURITY_CHECKLIST.md, README.md, and screenshots of your app with made-up data.
  • On Canvas only: reflections, exit tickets, your personal AI-use rules, the signed safety contract, self-assessments, written peer reviews, a pair's signed contribution statement, the capstone pitch, and your project submissions.
  • Never commit grades, feedback, reflections, classmates' real names (use GitHub usernames), your student ID or anyone's real personal data.

The reasons, and the University policies behind them, are in Privacy of your work.

Templates and starters ​

  • Document templates: SPEC · TESTS · PROMPTS · PROJECT_README · AGENTS · SECURITY_CHECKLIST · CODE_REVIEW · REFLECTION. Copy a template into your repo and fill it in. (The reflection template is a shape for writing you submit on Canvas, not a file for your repo.)
  • Starter kits: the AI micro-app starts from weeks/09-apis-and-secrets/starter/, and the capstone from projects/capstone-starter/. The capstone starter already contains the document templates, adapted for the capstone, and tested feature patterns for a database, a chart and a public API. How to copy a starter into your own repo: Start a project from a starter.
  • Fallen behind on Project 1? The rescue starter is a working study timer in plain HTML, CSS and JavaScript, built from the week 5 example spec. If your own v1 doesn't work by week 7, talk to your instructor: you can continue from the rescue starter so you can still take part in weeks 7 and 8 (debugging, the function you write yourself, tests and walkthrough 1). Credit it in your README and PROMPTS.md; your own additions and documents are what's graded.

How to submit ​

Do this for every project deadline.

  1. Save everything to GitHub. Commit your work, then open your repo on github.com and check that your latest commit is there.

  2. Test the live site as a stranger would. Open the live URL in a private (incognito) window. If it only works on your computer, it isn't done.

  3. From week 10 (Vercel): use the production URL and take a screenshot. The production URL is your app's main, permanent address (for example https://fridge-chef.vercel.app), not a long preview link: Vercel deletes old preview deployments. Take a screenshot of the production site working.

  4. Copy the link to your final commit. On your repo page on GitHub, open the commit history (the clock icon or "N commits"), click the top commit, and copy the address from the browser bar. Menus move; if you can't find it, ask your chat assistant "How do I get the link to a specific commit on GitHub?"

  5. Submit on Canvas:

    • the repo URL;
    • the live URL (from week 10, the production URL and the screenshot);
    • the link to your final commit;
    • for the capstone final: the link to the v1.0 release and the demo video link.

    Reflections, peer reviews and other personal writing are separate Canvas assignments. They never go in the repo.

We grade the commit you submitted. You can keep working afterwards, but later commits only count if you resubmit before the deadline (or before your extended deadline if you use a grace token).

IMPORTANT

Keep project repos public unless you have a reason not to. GitHub Pages on a free account needs a public repo. A private repo is fine for the micro-app and capstone if it's on your personal account (Vercel's free plan can't deploy private repos owned by an organization) and you add your instructor as a collaborator. Public means anyone can read every file and every old commit, which is one more reason never to commit a secret.

Learning on your own? Add a link to each finished project on your home page. That list becomes your portfolio.
