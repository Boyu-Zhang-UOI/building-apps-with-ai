From Python to JavaScript ​

You already know how to program. This page shows how the ideas you know from Python look in JavaScript, and how a web page fits together, so that in week 1 you can read the code the AI writes for you.

ItemDetails
WhenWeek 0, before week 1 (or during it at the latest). Recommended, not graded
TimeAbout 60–90 minutes, at your own pace
ForAnyone who has taken a programming course in Python (or another language) but hasn't written JavaScript or built a web page
You needA laptop with Chrome, Edge or Firefox. Optional: the vc101-practice Codespace from step 4 of the pre-work, to run node
AI use🟢 AI on: ask a chat assistant to explain any example, or to give you another one · 🔴 AI off: the self-check at the end

Why this matters. In this course an AI writes most of the code, and almost all of it is JavaScript, the language web browsers run. Your job is to read that code, check it, and change it by hand. You don't need to write JavaScript from memory. You do need to read it well enough to spot a == that should be ===, or a missing await. Most of what you know carries over: variables, conditions, loops, functions, lists and dictionaries all exist. The spelling changes, and a few rules change in ways that catch Python programmers out. This page is about those.

Try every example yourself. Typing code, and seeing it run, teaches far more than reading it.

On this page: Running JavaScript · Values and variables · Arrays and objects · Functions, conditions and loops · Modules, errors and waiting · A web page · Five traps · Self-check

Part 1 — Two places to run JavaScript (10 min) ​

In Python you type python3 for an interactive prompt, or python3 hello.py to run a file. JavaScript has two homes: the browser, where web pages run, and Node.js, a program that runs JavaScript outside the browser (on servers, and in your terminal).

In the browser console ​

Every browser has DevTools, a set of panels for looking inside a web page. Its Console tab is an interactive JavaScript prompt, like Python's >>>.

  1. Open any web page, for example this one.

  2. Open DevTools: press F12, or Ctrl+Shift+J (Windows, Linux, ChromeOS) or Cmd+Option+J (macOS) in Chrome and Edge. In Firefox, use Ctrl+Shift+K or Cmd+Option+K. Click the Console tab if it isn't open.

  3. Type each line and press Enter:

    js
    2 + 3
console.log("Hello from JavaScript")

✅ Checkpoint: the Console shows 5, then Hello from JavaScript. console.log(...) is JavaScript's print(...).

WARNING

The first time you paste into the Console, Chrome may ask you to type allow pasting. That's a guard against a common scam: people are tricked into pasting code that steals their accounts. Only paste code you understand, such as the examples on this page.

In a terminal, with node ​

  1. Reopen your vc101-practice codespace from github.com/codespaces. Node.js is already installed there. (Or use Node on your own computer: local setup.)

  2. In the terminal, type node and press Enter. You get a > prompt. Type 2 + 3 and press Enter, then press Ctrl+D (or type .exit) to leave.

  3. Now run a file. Create hello.js with one line, console.log("Hello from Node");, and run it:

    bash
    node hello.js

  4. Stop the codespace when you finish this page, so it doesn't use up your free monthly hours (how).

✅ Checkpoint: the terminal prints Hello from Node. This is exactly like python3 hello.py.

Which one should I use? Either works for Parts 2–5. The browser console needs nothing but a browser. Part 6 needs a web page.

Part 2 — Values, variables and equality (15 min) ​

Variables: let and const ​

Python creates a variable the first time you assign to it. JavaScript asks you to declare it first, with one of two words (let and const):

python
# Python
count = 0
count = count + 1
TAX_RATE = 0.06      # a constant by convention only
js
// JavaScript
let count = 0;          // let: you may assign a new value later
count = count + 1;
const taxRate = 0.06;   // const: you can't assign a new value
  • Use const by default, and let only when the value must change. Assigning to a const again is an error, which catches mistakes early.
  • You'll see var in older code and some AI answers. It's the old way, with confusing rules. Ask for let or const instead.
  • Comments start with // (or go between /* and */), not #.
  • Semicolons end statements. JavaScript usually adds missing ones for you, but the course's code uses them, so keep them.
  • Names use camelCase (taxRate, addItem), where Python uses snake_case (tax_rate, add_item).

Two kinds of nothing. Python has one None. JavaScript has two, and you'll meet both in error messages:

  • undefined means "never given a value": a variable declared with no value, a property an object doesn't have, a function that returns nothing.
  • null means "deliberately empty". The browser returns null when you ask for a page element that doesn't exist.
js
let score;
score                                // undefined
const user = { name: "Ada" };
user.email                           // undefined: no error!
document.querySelector("#missing")   // null (try it in the browser console)

A bad number calculation doesn't raise an error either. It gives NaN, "not a number": Number("ten") is NaN, and so is undefined + 1.

Equality: always === ​

JavaScript has two equality operators. Use the three-character one, strict equality:

PythonJavaScript
Equala == ba === b
Not equala != ba !== b

The two-character == converts the types first, with odd results:

js
"5" == 5            // true: the string was converted to a number
0 == ""             // true
null == undefined   // true
"5" === 5           // false: different types, as in Python

TIP

If you see == or != in code the AI wrote, change it to === or !== unless there's a comment explaining why. It's one of the easiest real fixes you can make by hand.

Strings and template literals ​

Strings work much like Python's. Single and double quotes both work. For an f-string, JavaScript uses a template literal: backticks (`) with ${...} around each value.

python
name = "Ada"
print(f"Hello, {name}! You have {3 * 2} messages.")
js
const name = "Ada";
console.log(`Hello, ${name}! You have ${3 * 2} messages.`);
PythonJavaScript
len(s)s.length (no brackets: it's a property, not a method)
s.upper(), s.lower()s.toUpperCase(), s.toLowerCase()

Template literals can also span several lines, which is why AI-written code often builds HTML with them.

Part 3 — Arrays and objects (10 min) ​

Arrays are lists ​

An array is JavaScript's list.

Python listJavaScript array
scores = [90, 72, 85]const scores = [90, 72, 85];
len(scores)scores.length
scores.append(60)scores.push(60)
scores.pop()scores.pop()
scores[0]scores[0]
scores[-1]scores.at(-1) (scores[-1] is undefined)
scores[1:3]scores.slice(1, 3)
85 in scoresscores.includes(85)

Notice that push works on a const array. const stops you assigning a new array to the name, but you can still change what's inside it.

WARNING

sort() sorts as text, and changes the array. [10, 9, 1].sort() gives [1, 10, 9], because "10" comes before "9" alphabetically. To sort numbers, pass a comparison: scores.sort((a, b) => a - b). To keep the original, sort a copy: [...scores].sort((a, b) => a - b) ([...scores] makes a copy).

Objects are dictionaries ​

An object holds named values, like a Python dictionary. The keys don't need quotes, and you can read a value with a dot.

python
book = {"title": "Dune", "pages": 412}
print(book["title"])
book["read"] = True
for key, value in book.items():
    print(key, value)
js
const book = { title: "Dune", pages: 412 };
console.log(book.title);          // or book["title"]
book.read = true;
for (const [key, value] of Object.entries(book)) {
  console.log(key, value);
}
  • Object.keys(book) and Object.values(book) are like book.keys() and book.values().
  • A missing key gives undefined, not a KeyError. book.author is simply undefined. To check, use "author" in book.
  • JSON, the text format most web services use, looks just like an object with quoted keys. JSON.parse(text) and JSON.stringify(object) do what Python's json.loads and json.dumps do.

Part 4 — Functions, conditions and loops (15 min) ​

Blocks use braces, not indentation ​

In Python, indentation decides what belongs to an if or a function. In JavaScript, curly braces { } do, and conditions go in round brackets. Indentation is only for people reading the code, so keep it tidy anyway: badly indented code hides bugs.

Functions and arrow functions ​

python
def average(numbers):
    return sum(numbers) / len(numbers)

def greet(name="friend"):
    return f"Hi, {name}"
js
function average(numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total / numbers.length;
}

function greet(name = "friend") {
  return `Hi, ${name}`;
}

AI-written code often uses the shorter arrow function form. It's like a Python lambda, but it can also have a full body in braces:

js
const double = (x) => x * 2;      // like: double = lambda x: x * 2
const shout = (text) => {
  const loud = text.toUpperCase();
  return `${loud}!`;
};

Two differences from Python:

  • A function without return gives back undefined, as Python's gives back None. Forgetting return in a function with braces is a common bug: (x) => { x * 2 } returns undefined, but (x) => x * 2 returns the doubled value.
  • Calling with too few arguments doesn't fail. The missing ones are just undefined. JavaScript has no keyword arguments; code that needs named options passes an object instead: makeButton({ label: "Save", color: "green" }).

Conditions ​

python
if age >= 18 and not banned:
    print("Welcome")
elif age >= 13:
    print("Ask a parent")
else:
    print("Sorry")
js
if (age >= 18 && !banned) {
  console.log("Welcome");
} else if (age >= 13) {
  console.log("Ask a parent");
} else {
  console.log("Sorry");
}

and, or and not are &&, || and !. As in Python, an if accepts any value, not only true or false, and some values count as false. In JavaScript these are false, 0, "", null, undefined and NaN (they're called falsy). The difference: an empty array [] and an empty object {} count as true in JavaScript, where an empty list is false in Python. To check for an empty array, test its length: if (items.length === 0).

Loops ​

PythonJavaScript
for item in items:for (const item of items) { ... }
for i in range(5):for (let i = 0; i < 5; i++) { ... }
for i, item in enumerate(items):items.forEach((item, i) => { ... })
while lives > 0:while (lives > 0) { ... }
break, continuebreak, continue

Use for…of to loop over the items of an array. JavaScript also has a for…in loop, which looks like Python's but gives you the keys (for an array, the positions "0", "1", "2" as text). It's trap 4 below.

Part 5 — Modules, errors and waiting (10 min) ​

Modules: import and export ​

A module is a JavaScript file that shares some of its functions with other files. In Python every file is a module and anything can be imported. In JavaScript, a file must export what it shares.

python
# stats.py
def average(numbers): ...

# app.py
from stats import average
js
// lib/stats.js
export function average(numbers) { /* ... */ }

// app.js
import { average } from "./lib/stats.js";

The path starts with ./ (this folder) and includes .js. In a web page, a module needs <script type="module" src="app.js"></script>, and it only works when the page is served by a web server (a Codespace preview or GitHub Pages), not opened from your computer's files. The course's starters are already set up for this. In week 4 you'll move a function into a module so that you can test it.

Errors: throw, try and catch ​

PythonJavaScript
raise ValueError("Bad input")throw new Error("Bad input");
try: … except Exception as e:try { ... } catch (error) { ... }
print(e)console.error(error.message)
finally:finally { ... }
NameError (an unknown name)ReferenceError
js
try {
  const settings = JSON.parse(savedText);
  console.log(settings.theme);
} catch (error) {
  console.error("Couldn't read the saved settings:", error.message);
}

The errors you'll meet most are SyntaxError (the code isn't valid, so none of the file runs), TypeError (often reading a property of null or undefined) and ReferenceError (a name that was never defined, often a typo) (more). The Console shows each with a file name and line number. See try and catch in the glossary. Remember, though, that many JavaScript mistakes don't raise an error at all. They quietly produce undefined or NaN, which is one reason the course asks you to write tests.

Waiting: async, await and fetch ​

Some work takes time, such as asking a server for data. A browser can't freeze the page while it waits, so JavaScript doesn't stop on that line the way Python's requests.get(url) does. Instead, fetch (the built-in function for web requests) immediately returns a Promise: a placeholder for an answer that arrives later. You write await in front of it to wait for the answer, and any function that uses await must be marked async. If you forget await, you get the placeholder (Promise {<pending>}) instead of the data. You'll use this for real in week 9, when your page talks to your own server.

js
async function checkSite() {
  const response = await fetch("https://boyu-zhang-uoi.github.io/building-apps-with-ai/");
  console.log(response.status);   // 200 means OK
  const page = await response.text();
  console.log(page.length);       // how many characters came back
}
checkSite();

Part 6 — How a web page fits together (15 min) ​

A web page is three languages working together, each with one job:

LanguageJobPython-world comparison
HTMLStructure: the headings, paragraphs, buttons and inputs on the pageThe data the program works on
CSSStyle: colors, fonts, spacing, layout(none: Python programs rarely have a look)
JavaScriptBehavior: what happens when someone clicks or typesThe program itself

Here's a complete page that counts clicks:

html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Click counter</title>
    <style>
      body { font-family: sans-serif; text-align: center; }
      button { font-size: 1.5rem; padding: 0.5rem 1rem; }
    </style>
  </head>
  <body>
    <h1>Clicks: <span id="count">0</span></h1>
    <button id="add">Add one</button>

    <script>
      const countDisplay = document.querySelector("#count");
      const addButton = document.querySelector("#add");
      let count = 0;

      addButton.addEventListener("click", () => {
        count = count + 1;
        countDisplay.textContent = count;
      });
    </script>
  </body>
</html>

Read it from the top:

  • HTML is made of elements, written as tags: <h1>…</h1> is a heading, <button>…</button> a button. Elements nest inside each other. id="count" is an attribute: a unique name that CSS and JavaScript can use to find that element.
  • CSS rules pick elements with a selector (button, or #add for the element with that id) and set properties on them (font-size: 1.5rem).
  • The <script> comes last, so the elements already exist when the code runs.
  • The DOM (Document Object Model) is the browser's live version of the page, built from the HTML. JavaScript changes what you see by changing the DOM, not the file. document.querySelector("#count") finds an element using a CSS selector, and returns null if nothing matches.
  • Events are things that happen on the page: a click, a key press, a form being sent. addEventListener("click", ...) hands the browser a function to run every time the button is clicked (event and event listener). Notice that your code never calls that function itself. The browser calls it later, just as Python's sorted(words, key=len) calls len for you. A function handed over like this is a callback.
  • textContent puts text into an element. You'll also see innerHTML, which treats the text as HTML. Never use it for anything a user typed: the browser may run it as code (why).

Try it. Paste the page into a chat assistant with a live preview (as in step 3 of the pre-work) and click the button. Or save it as counter.html in your codespace and preview it with python3 -m http.server 8000 (how).

Then open DevTools on the running page:

  1. In the Elements tab, find the <span id="count"> and watch its number change as you click. That's the DOM updating.
  2. In the Console, type count and press Enter. You get the current count. Then type document.querySelector("h1").textContent = "I changed the DOM". The heading changes. Reload the page and it's back, because you changed the DOM, not the file.

✅ Checkpoint: you can point to the HTML that makes the button, the CSS that styles it, and the JavaScript that runs when it's clicked.

There's more on how pages, servers and requests fit together in How the Web Works.

Part 7 — Five traps for Python programmers (5 min) ​

Each of these has caught experienced programmers. When something "can't be wrong" but is, check this list.

1. + and == convert types quietly. In Python, "5" + 1 is a TypeError. In JavaScript it's "51". Anything read from an input box is a string, so input.value + 1 joins text instead of adding. Convert first with Number(input.value), and compare with ===.

2. A typo gives undefined, not an error. book.titel is just undefined, and undefined + 1 is NaN. The program keeps running and fails somewhere else, later. When a value is wrong, log it with console.log where it's made, not only where it's used.

3. === on arrays and objects compares identity, not contents. In Python, [1, 2] == [1, 2] is True. In JavaScript, [1, 2] === [1, 2] is false, because they're two different arrays. Compare the items, or the lengths, or use a test library's "deep equal" check (you'll meet one in week 4).

4. for…in isn't Python's for … in. On an array, for (const x in items) gives the positions as text ("0", "1"), not the items. Use for (const x of items).

5. Forgetting await. const data = fetch(url) gives you a Promise, not the data, and data.length is undefined. Put await in front, inside an async function: const response = await fetch(url).

One more that isn't a trap so much as a habit: indentation doesn't change what the code does. If the braces and the indentation disagree, the braces win.

Self-check (10 min) ​

🔴 AI off. Predict each answer on paper first. Then check it in the browser console or node, and read the answers below. If you get eight or more right, you're ready for week 1. If not, reread the part named in brackets; it's normal for this to take two passes.

  1. What does 7 / 2 give? And Math.floor(7 / 2)? (Part 2)
  2. What does "3" + 4 give? And Number("3") + 4? (Parts 2 and 7)
  3. True or false: "0" == 0. And "0" === 0? (Part 2)
  4. After const user = { name: "Kim" };, what is user.age? Does that line raise an error? (Parts 2 and 3)
  5. Rewrite this Python in JavaScript: print(f"{name} scored {score} points") (Part 2)
  6. What does [3, 20, 100].sort() give, and how do you sort the numbers properly? (Part 3)
  7. Rewrite in JavaScript: evens = [n for n in numbers if n % 2 == 0] (Part 3)
  8. What does this function return when called as half(10)? const half = (x) => { x / 2 }; (Part 4)
  9. Does if ([]) { console.log("yes") } print yes? (Part 4)
  10. In the click-counter page, what would happen if the <script> were moved to the top of the <head>, before the button? (Part 6)
Answers
  1. 3.5, then 3. JavaScript has one number type.
  2. "34" (a string: + joined text), then 7.
  3. true (the == converted the string), then false. Use ===.
  4. undefined, and no, there's no error. That's trap 2.
  5. console.log(`${name} scored ${score} points`);
  6. [100, 20, 3], because it sorts as text. Use [3, 20, 100].sort((a, b) => a - b).
  7. const evens = numbers.filter((n) => n % 2 === 0);
  8. undefined. The braces make it a full function body, and it has no return. Write (x) => x / 2 or (x) => { return x / 2; }.
  9. Yes. An empty array counts as true in JavaScript. Check items.length === 0 instead.
  10. document.querySelector("#add") would run before the button exists, so it returns null, and addEventListener fails with a TypeError such as Cannot read properties of null. You'll see that error in the Console. (Adding defer to the script tag, or moving it to the end of the body, fixes it.)
